## What you see

Every page of the site changes at once, without changing what it says. The page background is a pale blue-grey, the blocks are white panels with a thin line and rounded corners, text is small and even (14 px body, 11 px column heads in capitals), words are in Inter, every number is in JetBrains Mono so columns of numbers line up, and green, amber, red and grey are used the same way on every page (fits, check, bad, not judged). In dark mode the same colours are the dark set of the mockup. Chinese text uses the system Chinese font (no Chinese font is downloaded). The pages that are tables of cards today (market, macro, positions, risk, data health, base data, job console, settings, option data, company data, price lines, valuation, strategy replay) look like the mockup with no layout change: the same panels (1 px line, 8 px corners), the same title sizes, and a page column no wider than 1180 px on a wide screen.

`/options/candidates` changes in layout as well, as in the approved mockup: the company strip is three compact cards in a row (company, spot, buy price, next earnings, "n fit, n check, n collapsed" on two lines) instead of one full-width card per company; the legend is four short coloured boxes; the rows stay the expandable rows of today (open on click and on keyboard) under a coloured band for each tier, each row has a coloured stripe on the left, the badges are small tinted pills, and the run line is one sentence in mono instead of three pills. The page is not one HTML table: that would be a rewrite of the row component, and the look does not need it. On a phone (390 px) the rows stack as today and the strip is one column. Hint words keep the dotted underline; the Chinese explanation shows on mouse hover and on keyboard focus. It does not show on a tap on a phone: the long explanations stay in the legend boxes, which are always visible (Left out).

The other pages with a layout problem (tracking, result, underlyings, home, household, notices, structures, valuation import) get the new fonts, sizes and colours from this design and keep their layout; each gets its own mockup shown to the owner first, then its own design amendment (Left out).

## Goal

One shared theme, so that a page restyle is a layout change and not a colour and font change. The theme is the tokens of the approved mockup in `web/src/styles/theme.css`, read by the shared shadcn components through the existing `@theme inline` mapping. Four shared files hard-code Nova values that a token cannot reach (`card.tsx`, `table.tsx`, `badge.tsx` and the shell `App.tsx`): entry 1 edits exactly those, and no page file changes for the theme.

## Decisions

1. **System font stack first, packages second.** Entry 1 names the fonts in the stack and needs no package: `--font-sans` is `"Inter Variable", Inter, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif` and `--font-mono` is `"JetBrains Mono Variable", "JetBrains Mono", ui-monospace, Menlo, monospace`. Where the font is not installed the stack falls back, so the look is complete in colour, size and shape with system fonts. Entry 2 then adds the two files (Decision 2). Entry 1 does not wait for the crew whitelist.
2. **Fonts are self-hosted, nothing is downloaded from outside (entry 2).** `@fontsource-variable/inter` 5.3.0 and `@fontsource-variable/jetbrains-mono` 5.3.0 are direct dependencies (owner 2026-11-19 08:50Z; OFL-1.1, no dependencies, widely used, stable). Only the latin subset is bundled: the package has no latin css, so `web/src/styles/fonts.css` declares two `@font-face` rules (families `Inter Variable` and `JetBrains Mono Variable`, `font-display: swap`, weight range of the variable file) whose `src` is the package file `@fontsource-variable/inter/files/inter-latin-wght-normal.woff2` and `@fontsource-variable/jetbrains-mono/files/jetbrains-mono-latin-wght-normal.woff2` (both allowed by the `./files/*.woff2` export), and `web/src/index.css` imports it. Vite copies two hashed `woff2` files. This is a little own glue (two `@font-face` rules) instead of `wght.css`, because `wght.css` would copy ten or more unicode-range files; the rules sit behind the `--font-*` tokens, so a later package css can replace them. The Google Fonts link of the later candidates mockup is not used. Entry 2 is attached only after agent-crew says that the crew whitelist `rules/frontend-stack.md` revision `2026-11-19.1` (which lists both packages) has merged; this repository has no check of crew, so the order is kept by the window, and the acceptance of entry 2 only names the revision it copies.
3. **ADR 0034 is amended in entry 2.** The sentence "no web font download" becomes "no web font from outside; two self-hosted variable fonts (Inter, JetBrains Mono) are allowed", and the 16 px text rule becomes the scale of Decision 4; the 44 px target rule stays. The amendment is dated 2026-11-19 and cites ask 5217. Between the merge of entry 1 and entry 2 the ADR still says 16 px: this is accepted because entry 2 follows within the day the whitelist merges, and entry 1 says so in its pull request description. The edit changes the sha256 of the ADR, so entry 2 also updates `web/copy-manifest.sha256`.
4. **Text scale is the mockup's, and `text-base` changes.** Body 14 px / 1.45. Utilities: `--text-xs` 11 px, `--text-sm` 13 px, `--text-base` 14 px (it equals the body: today `text-base` is 16 px and is the title size of `CardTitle`; at 16 px it would be bigger than the 14 px body and 2 px off the mockup), `--text-lg` 15 px, `--text-xl` 17 px (the mockup's h2; the section titles of the pages use `text-xl`), `--text-2xl` 22 px (the mockup's h1; the page titles use `text-2xl`). Each has a line height of 1.45. So h1 and h2 are sized by the same utilities the pages already use, through `@theme` overrides in `theme.css`, with no page edit. The scale is monotone (11, 13, 14, 15, 17, 22). Column head 11 px capitals, letter-spacing .05em, weight 600, muted, is set in `table.tsx` (`TableHead`); badge 11 px weight 600 in `badge.tsx`; tooltip 12 px. A number is mono 13 px; every table cell and every number gets `font-variant-numeric: tabular-nums` through one base rule.
5. **Touch targets stay.** A button, toggle, tab and accordion trigger keeps the 44 px minimum height (the owner reads the pages on a phone); a table row is not a target.
6. **Palette is the mockup's, light and dark, with one nudge.** Light: page `#f6f7f9`, panel `#fff`, text `#1b2430`, muted `#5f6c7e` (the mockup's `#667385` is 4.50 on the page tint by a hair and 4.18 on the neutral tint; the existing contrast test asks 4.5 for muted on background, card and muted, so the muted text is darkened to 4.98, 5.34 and 4.63), line `#e3e7ed`, accent `#1f5fbf` on soft `#eef3fb`; good `#14794a` on `#e3f4ea`, warn `#8a5a00` on `#fdf0d5`, bad `#b3261e` on `#fbe4e2`, neutral `#566275` on `#eceff3`. Dark: page `#10151c`, panel `#171e28`, text `#e4e9f0`, muted `#8f9db0`, line `#283140`, accent `#7aa8f0`; good `#5fd39a` on `#173326`, warn `#e8b85a` on `#3a2e12`, bad `#f08a82` on `#3d1b19`, neutral `#a3b0c2` on `#252e3b`. The values replace the greys in `:root` and in the dark block; the existing token names are kept, and the tier names `--tier-fit`, `--tier-check`, `--tier-grey` (each with a `-soft` background) are added and map to good, warn and neutral. Colour is never the only signal: the tier is also a word, as today.
7. **Shape and spacing.** `--radius` is 8 px; a panel is a 1 px `--border` line with that radius: `card.tsx` drops `rounded-xl` and the `ring-1 ring-foreground/10` for `rounded-lg border border-border`, and its `--card-spacing` is 12 px for the default size (the mockup's 10 px 12 px is taken as 12 px all round, one value for the one shared component). `table.tsx` takes cell padding 7 px 10 px and head 8 px 10 px. `badge.tsx` is a pill with the tier tokens available as variants' colours. `--content-column` becomes `73.75rem` (1180 px) and `web/src/shell/App.tsx` puts `mx-auto w-full max-w-(--content-column) px-4 py-6` on `main` (24 px 16 px), so the claim is true by a file that uses it; the 45 rem of today is read by nothing and is replaced, not kept. The page background is `body { background: var(--background) }` and `Card` is `bg-card`.
8. **Chinese stays in the Go payload.** No entry adds a visible English or Chinese string in `web/src`. The candidates labels the mockup shows ("Tier", "Contract", "Margin of safety", "Below spot", "Premium-yield", "Badges") are payload fields today or they are not; entry 3 uses the field names that exist and does not rename a label. A label that must change is a payload change of module pages and needs its own issue after the screenshot step shows the need (Left out).
9. **A theme change must not hide data.** The mockup's company strip drops the valuation lines (they sit in the row detail). Entry 3 shows in the strip only the facts the strip carries today and moves no field out of the page; a field the payload gives for the strip and the row detail does not show is listed in the pull request description for the owner, not deleted.
10. **A page passes only after a screenshot.** The window, after the merge of each entry, compares a screenshot of the live `/options/candidates` and of one theme-only page with the mockup, and states every difference (owner rule). There is no ui-shot of `/options/candidates` in CI: a fixture for it would be the output of the Go page builder of module pages, which no web entry may write, so this design does not claim one (Left out). The theme-only pages are in ui-shots through their `web/fixtures/<dir>/ok.json`.
11. **Hints keep the tooltip they have.** The hint words of the candidates page are Radix `Tooltip` triggers (hover and keyboard focus, `aria-describedby` set by Radix while open). A tap on a phone does not open them. The smaller choice is taken: no change of `components/ui/tooltip.tsx`, no `Popover`; the explanations a phone needs are in the legend boxes, which are always shown. Tap-to-open through the whitelisted `Popover` (it is in `radix-ui` and `components/ui/popover.tsx`) is a later amendment if the owner finds the phone needs it (Left out).
12. **The candidates table stays an accordion of rows.** The look (tier band, stripe, pills) needs only classes on `TierView.tsx`, `TierRows.tsx` and the badge. One HTML `table` with a detail row would replace the Radix `AccordionItem`, the keyboard behaviour and the `max-sm` stacking of `TierRows.tsx`, which is a rewrite and not a restyle; it is not done. The stripe of today is 4 px (`border-l-4`) and stays 4 px with the tier colour.
