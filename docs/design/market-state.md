Goal: a page "Market state" for an option put seller. Five market rows (S&P 500 against its 200-day line, S&P 500 drawdown from its 60-session high, VIX, VIX against VIX3M, high-yield spread) and one sector table (11 sector funds and SMH, each as fund-minus-SPY over 21 and 63 sessions, with the rank among the 11). It says where each figure stands now: a level, and a percentile only where one is defined (VIX over 3 calendar years; the high-yield spread over the days we stored, "n days since the first stored day"). Every row prints its window and its own data day. Each market row is clickable and opens a line chart of that figure over its history. Under the sector table, a rotation map (one point per fund, with a four-point tail) and a bar chart of the 63-session gaps. The page prints how fresh the data is: sectors and SPY are daily closes, not intraday. It reflects the present: no prediction, no state word (no "risk-off", no verdict on any fund or on the market; the only words of the kind are the four fixed quadrant labels of the rotation map, Decision 15, which name a region of the plane and are never applied to a fund), no colour judgement, and nothing reads it (no gate, no rule, no alert, no sentence about a put).

1. What the page is. Title "Market state"; route `market-state`, page name `market_state_page`, schema `page.market_state_page.v1`, order 120. Nothing reads the page's figures.
2. The five market rows, fixed order, ids `sp500_vs_200d`, `sp500_drawdown`, `vix`, `vix_term`, `hy_spread`. Every row has a label, a figure (or a gap), a required `window` text, a required data day `day`, and a `history`. Examples, not data:

A level, no percentile.

The only row with a stored 3-year percentile.

Percentile is `short_history` (a gap text, the level still shown) under 250 stored days.
   Only `vix` and `hy_spread` carry a percentile, and only these two say how many days or years it covers; the other three are levels and the page says "level" in their window text.
3. The sector table: one block `sectors` with a required `caption`, a required `end_day` and rows. Rows are the 11 sector funds sorted by the 63-session gap, greatest first, gap rows last (ties keep manifest order), then one row `SMH` (semiconductors, group `industry`) under a rule, never ranked. Each row: symbol, label, gap over 21 sessions, gap over 63 sessions (fund percent change minus SPY percent change, points, signed, 2 places), and the rank at each window "3 of 11". The caption says: "Fund change minus SPY change over 21 and 63 sessions ending on `end_day`; a rank counts only funds with both closes; trial windows, not a forecast." `end_day` is SPY's newest close day (`Result.EndDay`). A gap row shows its reason, never a number. Under the table: the rotation map (Decision 15) and the 63-session bar chart (Decision 16).
4. The c0 rule (advisor). A fund is ranked in a window only if it has a close on SPY's newest day and on SPY's start day of that window (the day `spy.Days[back]`); otherwise its gap is `missing_input` (the rule of `sectorExcess`, `global.go:56` and `:98`) and it is left out of the rank. `Of` is the number of funds ranked in that window, so with one gap fund the page says "9 of 10", not "9 of 11". Rank 1 is the greatest gap; ties get the better position by manifest order. The benchmark gap is as `benchGap` (`global.go:44`): no SPY close is `no_data`, SPY's newest close more than 3 weekdays behind the page day is `stale_input`, and then every fund row of that window shows the gap. Entry 1 pins agreement with the report: its test feeds the same `CloseIn` data to `marketstate.Compute` with a window of 20 and to `pagefig.NewGlobal` and compares the gap text and gap reason of every fund.
5. Why 21 and 63, not 1, 5 and 20. `report.sector_excess` answers "what moved this week" for the morning report: 1, 5 and 20 sessions, rows sorted by 5 days (`global.go:32-36`, `sortByD5`). The owner's question is where money has stood over a month and a quarter (August to November), so this page uses 21 and 63 sessions, the same horizons as the tech layer of step 1 (`market-state-tech.md` Decision 3), so the two pages quote the same windows. They are new figures of this page, not a change of `report.sector_excess`: the report keeps its ids, windows and sort. The windows are the fields of `marketstateapi.Params` (trial constants, one function `marketstate.TrialParams()`), printed in the caption.
6. Where figures are computed. A new package `internal/compute/marketstate` (pure: no I/O, no clock, no store; exact decimal with `math/big` as `pagefig` does) behind the declarations-only `internal/compute/marketstateapi`, the same shape as `liquidity` behind `liquidityapi`. 8. The trend chart of each market row (owner requirement a). Where the history comes from: the stored series, not the stored readings. Readings exist only from the day `compute_figures` first stored them and drawdown has no reading, while the series can be loaded 5 years back (`ot series-load`). `marketstate.Compute` returns, for each of the five rows, the daily points of the figure itself over the newest 3 calendar years stored (at most 800 points, ascending) and the number of points before the cap. One formula, not a copy: the two registered rows are computed by the functions the registered figures use. `Input` carries `Figures compute.Figures`, `Units compute.Units` and `Rules compute.Rules` (the same objects `cmd/ot/wire.go:301` builds with `figures.New(stats, own.NewRolling(stats), sops, rules.New())` and `own.NewUnits()`); `marketstate` imports none of `figures`, `own`, `rules` or `gonumstats`, so no arch question arises. For each day `d` of the series, `sp500_vs_200d` is `Figures.MovingAverageGap("market.sp500_vs_200d", sp500[:d+1], d)` and `vix_term` is `Figures.Ratio("market.vix_term_ratio", vix[:d+1], vxv[:d+1], d)`, each rounded by `Units.RoundHalfEven(f.Value, Rules.Rule(id).Scale)`. What those functions and rules say, read in code at origin/main (`figures/series.go:45` and `:118`, `rules/rules.json`): value is float64 arithmetic (not exact decimal): `MovingAverageGap` is the newest close over the mean of the last N closes minus 1, N = 200, and with fewer than 200 points it is `short_history`; there is no check that the 200 points are consecutive sessions, they are the last 200 stored points; `Ratio` needs both newest points on the same day and a non-zero denominator (else `bad_input`); both rules have `max_age_days` 8 (the newest point against the as-of day, 0 days here) and `scale` 6, half-even, unit ratio (a fraction: 0.031200 is 3.12%). A figure that is not `ok` is not a point (no carry, no zero). The page shifts the decimal point two places for the display text of the first row. `sp500_drawdown` has no registered figure; it is exact decimal (`math/big`) in `marketstate`: each day's close against the highest of the 60 closes ending that day, percent, 2 places half-even, 0 or below. `vix` and `hy_spread` are the stored levels. A day missing in one calendar (a FRED holiday against a market day, or one leg of the ratio) drops that point, never carries the last value over; a day with only one of `VIXCLS` and `VXVCLS` is not a `vix_term` point. Entry 1 has one new test that feeds one series through `Compute` and through the real `figures.New(gonumstats.New(), own.NewRolling(...), own.NewSeriesOps(), rules.New())` and `own.NewUnits()` and asserts the same text for every day both produce, and that `Compute` produces a point on every day the figures produce one. The row prints the reading's day (`data_day` of the stored reading); the chart prints its own last day in its caption, and the two may differ by a day. The page copies the points into the row's `history` (Decision 10) and computes none; the front end draws them with the existing `Chart` (line, one series, categories the days) and computes nothing. The history depth is the stored depth. The page builder writes a required visible `caption` for every history: "<n> days, <first day> to <last day>", and "newest 800 of <N> days, <first day> to <last day>" when the cap cuts; a row with fewer than 2 points has `history` a gap `no_data` whose text says why.

15. The rotation map (owner, 2026-11-14). It follows the idea of the Relative Rotation Graph (de Kempenaer, StockCharts): a point per fund on two axes with a tail of past positions. It does not use the proprietary JdK RS-Ratio and RS-Momentum; the formula here is transparent and is the one of this page: x = the fund's 63-session excess over SPY (`gap_63`), y = the pace difference `gap_21 - gap_63 / 3` in percentage points (`gap_21` and `gap_63` are Decision 4's gaps, the table's two columns; y above 0 means the last month ran ahead of the quarter's average pace against SPY, relative momentum rising; below 0, behind it), both on SPY's newest day. Why not y = `gap_21` itself (owner round 1): the last 21 sessions lie inside the 63, so the two excesses are correlated by construction and the points line up on a diagonal, which makes the quadrants say little; the pace difference splits trend (x) from momentum (y) as the Relative Rotation Graph does, with a plain formula. y is computed in `marketstate` from the unrounded gaps (exact rationals) and rounded half-even to 2 places; the tail uses the same formula as of each tail session. One point per ranked fund and one for SMH (drawn, marked unranked). The tail is the same two numbers (x and y) as of the sessions 5, 10, 15 and 20 trading days before `end_day` (SPY's sessions at depth 5, 10, 15, 20 of the stored bars; chosen over "the four previous Fridays" because it needs no calendar rule and a holiday week still has its point), each computed by the c0 rule of Decision 4 with that session as the as-of day (the fund needs a close on that session and on the session 21 or 63 sessions before it; SPY is the benchmark). It needs 20 + 63 + 1 = 84 closes of the fund and of SPY; 140 calendar days of weekday bars hold 100 sessions, so the oldest tail point exists (entry 5 has a test with exactly 140 calendar days of weekday bars). A fund with fewer than 84 sessions loses the tail points whose depth needs more (the oldest first); with fewer than 64 sessions it has no today point, its `rotation` is a Gap and it is not drawn. Each point carries its own day as text (`text`, for example "Nov 6: 63-session +4.0, pace +1.3"), and the block caption (`rotation_axes.note`) states both windows (21 and 63 sessions) and the tail offsets (5, 10, 15 and 20 sessions before `end_day`). A fund with no close on a tail session, or one that fails the rule there, drops that tail point; the previous value is never carried. Each fund's `rotation` is the points oldest to newest (`{day, x, y, text}`), the last being today's; if today's point is missing (the fund has no figure at 21 or 63) its `rotation` is a Gap and the fund is not drawn. The four quadrants carry fixed text labels placed by the web at fixed corners: Leading (x above 0, y above 0), Weakening (x above 0, y below 0), Lagging (both below 0), Improving (x below 0, y above 0); they sit in the one file `quadrant.go`, are not coloured by any figure, and the block caption says the map shows position, not a forecast. All numbers are the page builder's (copied from `marketstate`); the web draws with the recharts scatter through the shadcn chart component (`ChartContainer`, on the frontend whitelist) and computes nothing.

    // Params are the trial constants. marketstate.TrialParams is their one source.
    type Params struct {
        HighSessions  int // 60: the window of the drawdown high
        ShortSessions int // 21: the short sector window
        LongSessions  int // 63: the long sector window
        MeanSessions  int // 200: the moving average of sp500_vs_200d history
        StaleWeekdays int // 3: SPY's newest close older than this many weekdays is stale (the rule of report.sector_excess)
        MaxAgeDays    int // 4: a newest series point older than this many calendar days is stale
        ChartYears    int // 3: the history window in calendar years
        ChartMax      int // 800: at most this many history points per row
        TailStep      int // 5: sessions between tail points
        TailPoints    int // 4: tail points before today's
    }

    // Input holds what the figures need. Day is the as-of day. Each series is ascending by day, nil when none is
    // stored. Benchmark, Funds and Industry are newest-first closes as decimal text (blockapi.CloseIn).
    type Input struct {
        Day                                   contracts.Day
        SP500, VIXCLS, VXVCLS, BAMLH0A0HYM2   compute.Series
        Benchmark                             blockapi.CloseIn // SPY
        Funds, Industry                       []blockapi.CloseIn // the 11 sector funds; SMH
        Figures                               compute.Figures    // the one the registered figures use (cmd/ot/wire.go)
        Units                                 compute.Units
        Rules                                 compute.Rules
        Params                                Params
    }

    // Position is the rank of a fund at one window: At 1 is the greatest gap, Of the number of funds ranked at
    // that window. Reason is set (and At, Of are 0) when the fund is not ranked.
    type Position struct {
        At, Of int
        Reason compute.Reason
    }

    // Fund is one fund. Gap21 and Gap63 are fund percent change minus SPY percent change, points, 2 places half-even;
    // Day is EndDay and Aux the window's start day (SPY's day at the window's depth). A missing figure has an empty
    // Value and a Reason (never 0). Rank21 and Rank63 are zero for an industry fund.
    type Fund struct {
        Symbol, Name   string
        Gap21, Gap63   liquidityapi.Num
        Rank21, Rank63 Position
        Rotation       []Spot // today's point last, oldest first, tail points that fail the rule dropped; empty when today's has no figure
    }

    // Spot is one position of the rotation map as of Day: X is the 63-session gap, Y is gap21 - gap63/3 (points, 2 places
    // half-even, from the unrounded gaps).
    type Spot struct {
        Day  contracts.Day
        X, Y string
    }

    // Point is one day of a history; Value is decimal text.
    type Point struct {
        Day   contracts.Day
        Value string
    }

    // Line is the daily points of one row over the chart window, ascending, at most ChartMax; Total is the number
    // of points before the cap (the page writes "newest 800 of N" from it). Sp500Vs200d and VIXTerm hold the
    // register's rounded text (a fraction, 6 places); a nil Figures leaves them empty.
    type Line struct {
        Points []Point
        Total  int
    }

    // History is the line of each market row.
    type History struct {
        Sp500Vs200d, Drawdown, VIX, VIXTerm, HighYield Line
    }

    // Result holds every figure of the page that this package computes.
    type Result struct {
        EndDay   contracts.Day    // SPY's newest close day; empty when SPY has no close
        Drawdown liquidityapi.Num // percent, 2 places, 0 or below; Aux is the day of the high
        Funds    []Fund           // the sector funds sorted by Gap63, greatest first, gap rows last, ties in input order
        Industry []Fund           // in input order, never ranked
        History  History
    }

    // Func computes the Result; no I/O, no clock (internal/compute/marketstate.Compute).
    type Func func(Input) Result
