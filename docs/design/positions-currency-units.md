## Owner decisions (2026-11-11, in the dispatcher window)

The owner's words were only: rename the units in place, and answer 5b (show fractional quantities); both in one design. Everything else below that is not these two is the dispatcher's reading and is named as such in Decision 6 and 7.

1. Rename the money units in place: `usd` / `usd_per_share` / `usd_signed` become `amount` / `amount_per_share` / `amount_signed`; the `currency` field names the money.
2. Show fractional stock quantities (the owner's answer b to the earlier question): `QuantityCell.value` is a number for stocks, options stay integer, a fractional position is no longer skipped, and the skipped note and count follow.
3. All are one design: one schema change, one digest change, one fixture sweep.

## Goal

On `page.positions_page.v3` (a) a money cell says what it is: the unit names the kind of amount (a total, a price per share, a signed change) and `currency` alone names the money, so the cost of a JPY stock is no longer `{"currency":"JPY","unit":"usd_per_share"}`; (b) a stock held in a fractional quantity is listed with its quantity, not dropped into the skipped count. The web test `web/test/pages/positions/PositionsPage.test.tsx` changes its one `usd_signed` unit to `amount_signed` so that `tsc` still passes.

## What main holds today (read at 868737fe)

1. `MoneyCell` (schema `$defs`, two places: `StockRow` side about L221 and `OptionRow` side about L661) has `unit` enum `usd`, `usd_per_share`, `usd_signed` and `currency` enum `USD`, `JPY`. The generic `Cell` (schema L23-L43, used by the trades table) has a `unit` anyOf enum whose second member is `usd_signed` (L28); the placeholder type has it as `Unit5` (`web/src/types/positions_page.v3.types.ts` L109). No builder code emits a generic `Cell` unit (`trades.go` builds `cell{Text, Tone}` only).
2. `rows.go` `money(s, currency, unit)` is called with the three names at four places (cost and price `usd_per_share`, unrealised `usd_signed`, open premium `usd`); the text and the symbol come from `currency` (`symbolOf`), the unit only picks the sign and the tone rule. The text always has two places: a JPY cost of 12300 reads `¥12,300.00` (`money2` and `body` in `money()`), not `¥12,300`.
3. `strings.go` has `textSkippedEnd = " rows with a non-integer quantity are not listed"`. The web draws `text` as given and reads neither `unit` nor `quantity.value` (`grep -rn 'unit\|quantity' web/src/pages/positions` finds no read of either); the contradiction is in the contract only.
4. Quantity: `QuantityCell.value` is `type: integer` (schema L687-L716, one `$defs` entry used by `StockRow` and `OptionRow`), `quantity()` in `rows.go` uses `wholeText` and returns false for a fractional quantity, `rowsOf` counts that position in `skipped` and does not list it. `quantity()` is also called by `trades.go` `tradeQuantity` with unit `""`.
5. Unrealised and value are computed on exact rationals (`pagefig/holdings.go` `holdingRow` parses `Quantity` with `big.Rat`), so a fractional quantity needs no change in compute.
6. Pages are built per request: `cmd/ot/positions_site.go` `buildPositionsPage` calls `positions_page.Build` on each request and `ot page` calls it once; `grep -n 'pages.Page\|\.Build(' internal/jobs` finds no caller, so no job (scheduler included) stores or caches page JSON. After a deploy no stored `usd_per_share` payload exists to fail validation; the only copies are the web fixtures and the golden file, which the issue sweeps.
7. Other schemas: `page.macro_rates.v3` already has the currency-neutral unit `ccy_amount`. `page.positions_page.v1` and `v2`, `household_page.v1`, `household_risk.v1`, `report_page.v1` and `v2`, `home_page`, `options_summary` and others carry the same `usd*` names; they are not touched (Left out).

## Decisions

1. The three kinds stay, the currency leaves the name: `amount` (a total), `amount_per_share` (a price per share), `amount_signed` (a signed change with a tone). `currency` is the only place a currency is named (the convention of `page.macro_rates.v3` `ccy_amount`).
2. The rename covers every place of `page.positions_page.v3.json` that carries a `usd*` unit name: the two `MoneyCell.unit` enums and the generic `Cell.unit` member `usd_signed` (which becomes `amount_signed`; the uppercase `USD` member of `Cell.unit` and the `UsdFigure` unit `USD` are a currency code, not a kind, and stay). The old three names are removed, not kept beside the new ones, so a payload that still says `usd_per_share` is rejected.
3. In place, `schema_version` stays 3, as `pages-real-data.md` issue 18 did for `views`: the page has no consumer outside this repository and no stored page JSON (item 6 above). The digest in `carryover.sha256` changes with the file.
4. No new currency. `currency` stays `USD`, `JPY`; an unsupported currency is still the gap `unsupported_currency`. The text rules of `money()` stay (two places, sign and tone only for `amount_signed`). The builder's text carries the symbol of the cell's currency and the web draws that text as given; the web computes and formats nothing.
5. Quantity of a stock is a number: `QuantityCell` is replaced by two `$defs`. `StockQuantityCell`: `unit` const `shares`, `value` `type: number` within the same bounds (-1e9 to 1e9), `text` as today. `OptionQuantityCell`: `unit` const `contracts`, `value` `type: integer`, same bounds. `StockRow.quantity` refers to the first, `OptionRow.quantity` to the second; `QuantityCell` is removed. A fractional option quantity is therefore rejected by the schema (owner: options stay integer).
6. The quantity text rule (stocks): the sign is `−` (U+2212) as today and absent for zero; the integer part has no leading zeros and at most 10 digits; the fraction has trailing zeros removed and at most 6 places; no digit grouping (as today). `10.250` reads `10.25`, `0.5` reads `0.5`, `200.0` reads `200`, `-0.5` reads `−0.5`; `value` is the same number without the U+2212 (a `-` sign). The caps of 6 places and 10 integer digits, and skipping a stock quantity over them or a non-number (counted in `skipped` and named by the note, Decision 7, never rounded), are the dispatcher's choice, not the owner's; the 10 digits are today's `maxInt`, the schema bound is 1e9. An option quantity must be whole (a fraction of only zeros is whole, as today); a fractional option quantity is counted in `skipped`.
7. A skipped row is not listed, and the page-level note "Skipped: N rows whose quantity cannot be shown are not listed" (`builder.go` L246-L248, appended to `notes`) states it, so nothing is hidden without a word; the note is not a gap. A fill that cannot be shown keeps the cell gap `missing_input`. The skipped note names the new reason: `textSkippedEnd` becomes `" rows whose quantity cannot be shown are not listed"`; the `Skipped: N` count and its place in `notes` do not change. `trades.go` `tradeQuantity` passes unit `shares` for a stock fill and `contracts` for an option fill (it passes `""` today), so a fractional stock fill shows as a number with the same rule as a position (at most 6 places, trailing zeros dropped, e.g. `0.5 shares`); a fractional option fill, or a stock fill with more than 6 places, stays the gap `missing_input` (the dispatcher's reading of answer 5b: a fill is a quantity too; not the owner's words).
8. The web changes only its inputs: the hand-written placeholder type (`Unit1`, `Unit3`, `Unit5`, and `QuantityCell` split into `StockQuantityCell` and `OptionQuantityCell`, `Value5` stays `number`) and the four fixtures that the schema must still accept (`bad-version.json` keeps its bad version and takes the new unit names so that it fails for the version only). No fixture gains a fractional quantity: the contract test builds that case from `ok.json` in memory. The one test file `web/test/pages/positions/PositionsPage.test.tsx` sets `unit: 'usd_signed'` on a generic `Cell` of a v3 row (L142) and takes `'amount_signed'`, else `tsc` fails after the rename. No `.tsx` under `web/src` is edited (nothing in `web/src/pages/positions` reads `unit` or `quantity.value`), so there is no UI code and no frontend-stack line. The currency stays visible through the builder's `text` (symbol and digits) and the `currency` field; the web computes nothing and reads no unit to draw it.
9. Code generated from `contracts/` is not touched: `contracts/generate.sh` does not emit page schemas and `internal/contracts/gen/**` and `web/src/generated/**` hold no type of this schema (design 18 Files). The placeholder type is edited by hand as issue 18 did and the pull request says so.

## Left out

- A fractional option fill and a fill over 6 places stay the gap `missing_input` (options stay integer).
- A fractional quantity in the web fixtures: no fixture gains one, the contract test builds the case from `ok.json` in memory, because no `.tsx` reads `quantity.value`.

- A currency symbol or amount computed on the web (AGENTS.md: the web renders data and computes nothing).
- More currencies than `USD` and `JPY`; more than 6 places of a stock quantity (skipped, not rounded).
- Rejected alternatives. Adding `jpy_per_share`, `jpy`, `jpy_signed` beside the three: the enum doubles for each currency and the cell still names the money twice. One `QuantityCell` with `value` number for both rows: a fractional option would pass the schema.
