# Option contract lists: the real contract list of every watched US stock, taken in the evening and again before the open

Author: the optdesk designer (draft)
Owner approved: (pending)
Date: 2026-11-11
Revision: 8 (design A of two; design B, the ladder, accounting, floor and page, is a file not on main yet and cites this one; revisions 1 to 7 are kept beside this file as `option-contract-lists.v1.md` to `.v7.md`, outside the repository; the reviews of revs 1 to 7 and the verdict at 5003c44d are folded in and answered in `## Adversarial`). This design supersedes no sentence of `option-open-pull.md`: its per-strike path stays true and keeps running.
Status: under review. Read on origin/main at fdbc5a50 (it differs from c3503656 only in `internal/store/underlyingpg`). Probe files in `probes/listchains/`: `raw.txt`, `per-expiry.txt`, `parallel.txt`, `probes-5-6.txt` (read-only, port 4001). "[unverified]" marks a claim not checked in code, docs or a probe.

Goal. The seller needs the real contracts, with con_ids, of every watched US stock stored before the open, without depending on the day before (owner, 12:36Z: "必须有兜底方案"). Today the per-strike resolve guesses strikes and asks IBKR one by one. One `reqContractDetails` per (underlying, class, expiry) with no strike returns the real list, calls and puts together (`probes-5-6.txt`). This design adds that call and two new jobs that use it. It changes no existing job, no page and no plan; main's per-strike path keeps running beside it as the fallback. Design B consumes the stored lists. The indexes SPX, NDX and RUT are not in this design (`## Left out`).

## What main holds today

- `ContractsService` has `ListChains` and `ResolveContract` only. `broker.Broker` has no list call; `ReferenceClient` and `HistoryClient` are separate interfaces beside it.
- The details lane (`pacing.py`): timeout 20 s, then a 30 s pause, so a timeout costs 50 s; shared with dividends and bars. `parallel.txt`: 8 and 16 parallel calls finish in exact 5.0 s steps, so list calls do not overlap. **Every number below is 5.0 s per request.**
- The runner gives `Run` one key per call (`runkey.go:76`); `reconcileOn` runs the keys of a plan one after the other. Main's resolve jobs plan one key per stock, so each stock has its own budget clock and there is no order across stocks. Without `Bounded` a run bound is 30 minutes, and the deadline is max(window close, now) + bound (`runkey.go:253`). `verdict()` (`runkey.go:172-196`): a run with `Err` of kind `NoValue` is `no_value`; any other `Err` is a failed run (Retryable before the close is not counted and is retried each turn; after the close it expires); with `Err` nil, a job that implements `runner.Postcondition` (`internal/runner/api.go`, `Postcondition(ctx, day, datasetID, subjectKey string) (bool, error)`) marks the key present exactly when it answers true, and a false answer is a done run without a mark, which counts and is not run again (`nextAttempt`); without a Postcondition the mark needs `Usable > 0` and an empty answer before the close is `empty_before_close`, retried each turn. A run cut with `Returned > 0` is `partial` and runs again the same day; a crashed lease is re-run (`reconcile.go` `nextAttempt`).
- `runner.Scheduled`, `runner.Windowed` and `runner.Bounded` are optional methods with plain values on a job (`internal/runner/api.go:92-113`; `resolveJob` has them, `listed.go:97-104`), so a job package needs no edit of `internal/jobs/api.go`. A window is the session close plus a non-negative offset (`window.go`), so it closes at 16:00 at the earliest. `parseManifest` needs `budget_minutes` above 0, `[params]` and an `after_close` window (`manifest.go:80-100`). `stocks()` keeps US stocks only (`inputs.go:76`). `jobs.WatchEntry` carries `BuyPrice` (`internal/jobs/api.go:23`) in `Stored.Watch`.
- `option_open_resolve` runs at close+60m (17:00 ET), `option_open_resolve_gap` at open-90m (08:00 ET), `option_eod` at close (16:00, `run_bound` 16m, so cut near 16:16), `fundamentals` at 08:00 ET, `option_ledger` at close+60m (no window), the JP plan at open-45m (18:15 ET in winter); one worker (`ticker.go`), `reconcileTimeout` 2 h.
- `store()` writes the broker's strike text (`req.Strike`, listed.go:419), which is the broker's canonical decimal text; `strikeKey` (`inputs.go:130`, `RatString`) is for matching only: "12.5" becomes "25/2". `putOptionSQL` sets `resolved_at = now()` on every upsert and nothing reads it.
- `transport.py` (owner-only; 771 lines) registers `ContractsServicer` in `build_server`, so a new rpc is a method on that class. `ibgateway.py` has 799 lines; the ratchet fails a file over 800 not in `ratchet.json`, which is owner-only. `transport.py` imports generated types only through `pyside/src/optdesk/contracts/api.py`; the generated servicer's methods are abstract for mypy, so every subclass (`ContractsServicer`, `_FakeContracts` in `tests/contracts/test_contracts_api.py`) gains the method in the same change. gRPC has its default 4 MB message limit (no option on main); the largest answer probed is 516 contracts, about 50 KB.
- pyside deploy is the owner's (`docs/deploy/pyside.md`).

## Decisions

1. **The rpc.** `ContractsService.ListContracts(underlying, expiry, right, trading_class) -> ListContractsResponse{ repeated ContractSpec }`: one `reqContractDetails` with no strike; an empty `right` means both rights in one answer (Decision 7); con_id, right, strike, multiplier, class per contract. Read only. A timeout, disconnect or gateway error is a gRPC error, never a partial list (IB returns the whole detail list or an error). `list_contracts` joins the log `WORDS`, and `ListContracts` the live `ALLOWED_RPCS` (rpc names, checked against the stubs by `test_guard.py`), as a read.
2. **Where the pyside code lives.** New file `pyside/src/optdesk/ibkr/lister.py`: `ListingGateway(IbGateway)` adds `list_contracts` on the details lane as `resolve` does, formatting every strike with the existing `_decimal_text` (the table's CHECK at `migrations/0032_option_contract.sql:18` is `^[0-9]+(\.[0-9]+)?$` on `strike` text, and the key has `strike` as text, so "12.5" and "12.50" would be two rows); `ibgateway.py` is not edited. New file `list_rpc.py` (under 200 lines): validation, the answer, the proto conversion. A protocol `ListerGateway` in `model.py`, as `AccountGateway` and `ExecutionsGateway`, not a method of `Gateway`, so no fake of `Gateway` breaks. `server.py`'s default `build` is `ListingGateway`. **The edit of `transport.py` is the delegating method and nothing else**: an import, the method on `ContractsServicer` (UNIMPLEMENTED when the gateway has no `list_contracts`; else `self._shared.call("list_contracts", context, list_rpc.answer(...))`) and the word in `WORDS`; at most 15 lines, 771 to at most 786 before `ruff format`; the pull request states the count after formatting, and the entry fails if it is over 800.
3. **Go side.** `broker.ContractLister` (`ListContracts(ctx, underlying Contract, expiry Day, right, tradingClass string) ([]Contract, error)`, `right` empty for both) beside `Broker`; `Dial` still returns `Broker`; the concrete client implements both. UNIMPLEMENTED from an old service is `broker.ErrNotServed`, declared in `api.go` as a typed constant error (a string type `notServedError` with a one-line `Error` method, and the constant), not a `var`, so the interface file holds a type and a constant and no runtime value; the client returns it inside a Permanent error and `errors.Is` finds it (a comparable constant). The client keeps only contracts of the requested class and returns each contract's multiplier; **the multiplier filter is applied by the job (entry 5)**, which drops a contract whose multiplier differs from the chain's from `ListChains`, because `ListContracts` takes no multiplier. Strike text is the form main already stores: the Python side formats the float strike of a contract detail with `_decimal_text` (`ibgateway.py:143`: "660", "12.5", no trailing zeros), as it does for `ListChains` strikes that `ResolveContract` echoes.
4. **Two new jobs, one runner key each, their own parser and values.**
   - *Jobs.* `option_list_evening` (close+30m, 16:30 ET, order 115: after `option_candidates` 110, before `option_open_resolve` 120) and `option_list_preopen` (open-120m, 07:30 ET, order 185: before the gap's 190). `Plan` returns **one** key: dataset `master.option_list`, subject `evening` or `preopen`. `Run` gets all names in one call (`runkey.go:76`), builds every group, sorts the calls once and stops at one clock: held names, then **priority names** (a `Stored.Watch` entry with a non-empty `BuyPrice`, the owner's price), then the rest; inside a class, nearest expiry, then symbol; a name whose `ListChains` expiry set differs from the stored lists goes first in its class. Priority is bounded by the budget only; held is guaranteed (Decision 9). The jobs do not go through `cmd/ot/listedjob.go`: the one key does not depend on the names, and `Run` reads the stocks at its start.
   - *Parser, window, bound.* `list.go` has its own parser and its own `Schedule()`, `Window()` and `RunBound()`. Evening: window `after_close`, `lateness_hours` 5 (as the resolve), `RunBound` 92 minutes. Pre-open: window `after_close`, lateness 0 (closes 16:00), `RunBound` 31 minutes. A bound is the budget plus 50 s plus slack. The evening bound never binds: the deadline is the window close (21:00) plus the bound, and the 90-minute budget cuts first. The pre-open bound (16:00 + 31 minutes for a 07:30 start) never cuts a normal run either; it matters only for a start after the close. The job's own budget and `stop_time` are the cuts. Without `RunBound` the default 30 minutes would apply.
   - *Budget and stop time.* `list_budget_minutes` 90 (evening) and 30 (pre-open: 07:30 to 08:00). The pre-open job also has `stop_time` = 08:30 ET (initial value), a clock time in code: a window cannot end before the plan at 08:45; the stop time bites only on a late start (a down gateway at 07:30, a long earlier turn).
   - *Postcondition and the end states.* **Session.** A list serves the open of one trading day. `option_list_preopen` of key day D writes session D; `option_list_evening` of key day D writes `NextSession(D)` (`internal/clock/api.go:31`), the day whose open it serves, so the pre-open of D+1 finds the evening's groups listed for D+1 and lists only what is left. Run rows carry the same session. `Postcondition(ctx, day, datasetID, subjectKey)` maps to it: preopen reads session `day`, evening reads `NextSession(day)`. **Definitions.** `listed` of a run row is the number of groups with `listed_session` equal to the session and `listed_pass` equal to this pass, recounted from `master.option_list` (never from a counter, so a crash between the `option_list` row and the run row loses nothing). `expected` is the groups of that name not yet listed for the session when the pass's first run computed them from `ListChains`: set once, never recomputed by a re-run, `null` (unknown) until that name's `ListChains` answers; expected 0 gives reason `none`. **The job implements `runner.Postcondition`**: true when, in the run rows of that session and pass (`OptionListStore.ListRuns`, entry 3), some name has `listed` above 0, or there is at least one row and every row has reason `none` (the pass had nothing left to list, for instance the evening listed it all). This agrees with `verdict()` (`runkey.go:175-185`: with `Err` nil and a Postcondition, `Usable` is ignored and the mark is the Postcondition's answer, true meaning the data exists, not that this run wrote it). `Usable` is set to the groups listed, for the log only. **One rule: when this pass has listed nothing and some name has `expected` above 0 or unknown, the run ends Retryable for every reason except `stop_time` and `unserved`** (`timeouts`, `listchains_failed`, `broker_down`, `budget`, `list_max_new`, and `all_short`: every group ended `short` or `error`); **`unserved` ends Err nil and expires `no_value` on purpose** (main's per-strike path covers the day, and the run rows and the log name it); in every other case `Err` is nil (a pass that listed something, then ended on its budget, `list_max_new` or two timeouts; a pass with every name `none`; a late start). A Retryable run before the window close is not counted and is retried each turn, paying its `ListChains` and first calls again (Decision 10 gives the cost); after the close it expires, visible. **A run that starts after `stop_time` reads the stored rows only and makes no broker call at all (no `ListChains`, no `ListContracts`)**; it writes no new reason over a finished row, and for a name with no row of its pass it writes a row with `expected` unknown and reason `stop_time`; it ends Err nil. With something listed by this pass the Postcondition is true; with no row of its pass it is false, so it is one counted done run without a mark, not retried, and the key expires after the close as missing, visible (the pass did not run that day, intended; a late start after an evening that listed everything also reads missing, by the same rule). **Re-run cost:** a run reads its rows first; if every row is `none` it returns without any call; for a name whose `expected` is known it lists the remaining groups of that set that have no row listed for the session, without `ListChains`; for a name with `expected` unknown it calls `ListChains` first. "No broker call" below means no `ListContracts` call: a first pre-open run still pays `ListChains` for 45 names (Decision 9). Tests, one per case in entry 5: `TestPassListingNothingIsRetryable` (every call times out and `ListChains` always fails at 07:30: Retryable, key not present); `TestCompletePassThenCrashedRerunIsPresentWithoutCalls` (every row `none`, a re-run: Err nil, zero broker calls, key present); `TestLateStartMakesNoCallAndIsNotPresent` (clock 08:31, no row of the pass: Err nil, zero broker calls, every row `stop_time`, key not present, no second run); `TestPartialPassThenRerunAfterStopTimeIsPresent` (an earlier run listed names, a re-run at 08:31: key present); `TestAllShortIsRetryable` (every group answers short or error, nothing stored: Retryable with reason `all_short`, key not present); `TestPreopenStopsAtStopTime` (fake clock 08:29:55, a request of 10 s, one more group: the second request is not made, reason `stop_time`); `TestEveningHalfThenPreopenFailsIsRetryable` (the evening of D-1 lists half the groups for D, the pre-open of D fails every call: its expected is the other half, listed 0, Retryable, key not present); `TestEveningListedAllThenPreopenIsPresentWithoutListContracts` (the evening listed everything for D: the pre-open rows are expected 0, reason `none`, key present, no `ListContracts` call); `TestEveningWritesNextSession` (the evening of key day D stores `listed_session` NextSession(D) and its run rows carry it; the pre-open of D stores D, so the verdict's own case, an evening and a pre-open with one key day, no longer shares a session); `TestRerunAfterCrashBetweenListRowAndRunRowCountsIt` (the run dies after the `option_list` row of a group and before its run row: the re-run recounts and `listed` equals `expected`).
   - *Reconcile re-runs.* A run cut at `reconcileTimeout`, or a crashed lease, runs again the same day (the runner marks a cut run `partial` when `Returned` is above 0 and `abandoned_stop` otherwise; the job sets `Returned` to the groups it listed in that run, and both are re-run). The re-run reads its rows first (above), skips groups already listed for the session, and before `stop_time` it continues; after it it is the late-start case; `listed` is recounted from the table and `expected` is never recomputed, so a no-op re-run changes neither. A pass that listed something and ended on its budget ends Err nil and the Postcondition is true, so it is present and is not re-run; the next pass continues.
5. **Until pyside is restarted.** The first `ErrNotServed` ends the pass with `Err` nil (not an error kind): every name's run row gets reason `unserved`, the log line says `list_unserved: the pyside service has not been restarted`, the Postcondition is false, so it is one counted done run without a mark and the key expires `no_value` after the close, on purpose: the list passes did not run that day, and main's per-strike jobs, which run at their own slots as today, cover it. The ledger keeps no names and `safeErrText` cuts at 300 bytes, so names live in the run rows and the job's summary line (`Log`). The owner restarts pyside (Rollout).
6. **The writer and the records.**
   - *Writer.* Its own function in `list.go` (`listed.go`'s `store` needs a `keyRun`, `resolveJob` and `candidate`): per contract `Instruments.ResolveInstrument` (instrument from `osiOf`, same package) and `Options.PutOption` (`ListDeps` embeds `Stored`, which has both). **The strike is stored as the broker gave it, unchanged, as `store()` does (`listed.go:419`)**; **matching uses `strikeKey`** (`refKey`, `listed.go:343`), never the stored text. "Already stored" is one `ListOptions` read per name, matched on (right, strike by `strikeKey`, expiry, class); only new contracts are written, and the marks of what it lists are removed.
   - *Bounds.* Writes run inside the budget clock and stop at `list_max_new` = 60000 contracts per pass (initial): the first pass on an empty store lists about 180 groups of 200 to 500 contracts (both rights), 36 to 90 thousand, each a `ResolveInstrument` and a `PutOption` of unmeasured time, so it may end on the budget or the cap and the next pass continues.
   - *Real list.* A list is real when the call succeeds, both rights are present, it is not empty for an expiry `ListChains` lists, and it holds at least half (`list_min_ratio` 0.5) of the stored contracts of that group; otherwise the group keeps its older contracts and the outcome is `short` or `error`.
   - *Tables* in migration `0034_option_list.sql`. **`master.option_list`**, one row per (underlying, expiry, class) asked: `listed_at`, `listed_session` (the session of Decision 4: the trading day whose open the list serves), `listed_pass` (`evening` or `preopen`, the pass that listed it), `count`, `tried_at`, `outcome` (`listed`, `short`, `error`). **`master.option_list_run`**, one row per (session, pass, underlying): `expected` (the groups left to list when this pass's first run computed them, a list of `expiry|class`, `null` until the name's `ListChains` answers), `listed` (groups with `listed_session` equal to the session and `listed_pass` equal to the pass, recounted from `master.option_list`), `reason` (`not_finished`, `none`, `listchains_failed`, `budget`, `stop_time`, `timeouts`, `unserved`, `broker_down`, `list_max_new`, `all_short`), `updated_at`. Rows are written at pass start with `expected` null and reason `not_finished`, and updated per name as it ends, with writes that survive a cancelled context (`context.WithoutCancel`), so a crash or a cut leaves rows that read not finished; null counts as not none. `expected` is set once (the first non-null write wins); `reason` is the latest, but **a re-run writes a reason only when `listed` is below `expected`**, so a no-op re-run never replaces `none` on a complete row; expected 0 is `none`. **A watched US stock with no row for a session and pass is a gap** (the pass did not reach it or died before writing; the run writes a row for every name of the stocks it read at its start, `Run` reads the stocks once). **What B may rely on:** a contract row is current for an open when `listed_session` equals that open's day; the evening of D-1 and the pre-open of D both write D, and a group listed by either is skipped by the later pass of the same session. B reads both tables.
   - *Order of writes.* Contracts first, then the `option_list` row (with `listed_session` and `listed_pass`), then the run row: a failure between leaves the group listed by this pass and the re-run skips it, and recounts it into `listed` from the table. `short` and `error` update `tried_at` and `outcome` and keep `listed_at`, `listed_session` and `listed_pass`; a second `short` on a later session is accepted. A group "listed for a session" is `listed_session` equal to that session, never `resolved_at`. Age is in trading sessions: `NextSession` is the first session strictly after a day, so age is a loop of at most 5 calls. Role `ot_w_option_open` (INSERT, UPDATE, SELECT on both; no page role); B's migration is numbered after 0034.
7. **Classes and rights; one request per (underlying, class, expiry).** Class per stock: the symbol's own class; adjusted classes (`2SPY`, `2NVDA` in `raw.txt`; multiplier 100, so a multiplier filter would not drop them) are never asked and B names them as left out. **The right is always left empty**: SPY 20261218 unset gave 516 contracts (258 C, 258 P) in 0.84 s, against 4.49 s for the puts alone and 4.98 s for the calls; strike sets equal, con_ids distinct, the unset answer is their union; a contract is matched on (right, con_id). So calls of every name cost nothing extra: both rights are stored, the plan uses puts for non-held names and calls for held ones as today, and there is no per-right key and no carve-out for held calls. It is one sample of the unset case: an answer with only one right for an expiry is `error` and the group keeps its older contracts. A month string (`202612`) returns every expiry of the month (SPY: 5 expiries, 1034 puts, 15.6 s, the sum of five calls), gains nothing and comes near the 20 s timeout: **requests stay per expiry**. Latency is 1 to 7 s whatever the rows (QQQ daily 161 puts 6.5 s, QQQ monthly 352 puts 7.2 s); 5.0 s stays the planning figure.
8. **Expiry choice, `ChooseExpiries`** (a pure function in `list.go`; B applies it in the plan so a list is never taken for an expiry the plan drops). `max_expiries` is **pending the owner**: (a) the nearest N to DTE 30; (b) weekly expiries up to N weeks and the next two monthlies; (c) everything within N days. Initial value: (a) with N = 6 plus the next two monthlies if not among them (`keep_monthlies = 2`), so the expiry a seller uses is never dropped; a name with fewer keeps all. Held contracts of dropped expiries are not lost (the held path unions them); watched ones are named in B.
9. **Arithmetic at 5.0 s, per (underlying, class, expiry).** Inputs are assumptions: 45 US stocks, 12 held, 5 daily-expiry names (SPY, QQQ, IWM and the like) at 8 expiries each, 40 others at **3.5 expiries each (an assumption, not a measurement)**: 40 + 140 = **typical 180 requests, 15 minutes** (22 at 7.3 s). Worst, every name 8 expiries: 360 requests, 30 minutes (44 at 7.3 s). The 90-minute evening pass holds both. The budget is checked between calls, so a lane timeout (50 s) overshoots it by that much. These are IB calls only; Decision 6 states the writes. Pre-open: `ListChains` for 45 names as 5.0 s calls is 3.75 minutes [unmeasured], leaving 26.25 minutes = **315 requests** inside the 30-minute budget: the typical 180 are listed for the session by 07:49 when the evening listed nothing for it; when the evening listed some, the pre-open pays `ListChains` for all 45 names and lists only the rest; in the worst case 315 of 360. Held is guaranteed: 12 names x 8 expiries = 96 requests = 8 minutes. Priority has no bound but the budget. Two consecutive timeouts stop the pass (`stopAfterTimeouts`, `listed.go:35`).
10. **Collisions on the one worker, named.** *Pre-open:* 07:30 to 08:00 by budget, at most 08:01 (one 50 s timeout), so it ends before `fundamentals` and the gap at 08:00 and the plan at 08:45. If the gateway is not up at 07:30 (probe 3 pending) the key is retried each turn and never starts after 08:30 (Decision 4); a late run delays `fundamentals` and the gap (budget 40 minutes from their start, unchanged on main), so the gap can end near 09:10 and the plan waits behind it: the cost of a late gateway, bounded by the stop time. *Evening:* `option_eod` is cut near 16:16, so the pass starts at 16:30 and runs to 18:00 at most, ahead of `option_ledger` and `option_open_resolve` (17:00); typically it ends at 16:45 and nothing waits; in the worst case they start up to an hour late and the JP plan at 18:15 ET waits behind them (a delay, not a failure). A turn beyond `reconcileTimeout` (2 h) is cut and the run is `partial`.
11. **Probes pending, and what holds without them.** Probe 3 (gateway at 06:00 to 08:00 ET): default 07:30 with the retry and stop time of Decision 4; nothing claims the gateway answers early. Probe 5 (daily-expiry counts): the arithmetic uses the cap. Probes 6 and the QQQ and SPX parts of 5 are done (Decision 7). An empty answer for an expiry `ListChains` lists is `error`, recorded and named. Probes 7 and 8 belong to B.

## Adversarial

Rev 4 answers the review of rev 3, then earlier points.
- *Strike text (B2).* Adopted: the broker's text is stored unchanged, `strikeKey` only matches ("25/2" would break `strike::numeric`); acceptance: one row for a list and a per-strike contract (Decision 6, entry 5).
- *Window, bound, end states (B1).* The one rule, checked against `verdict()` (`runkey.go:172-196`): the job implements `Postcondition` (true when a row of this pass has `listed` above 0 or every row is `none`, read with `ListRuns` for the pass's own session), and `Err` is Retryable only when this pass has listed nothing and some name has `expected` above 0 or unknown, and the reason is not `stop_time` or `unserved`; otherwise nil. So a pass that lists nothing is retried and, after the close, expires visibly; a re-run after a complete pass and a crash is present, makes no call and is not reported missing; a late start reads stored rows only and makes no broker call, and with no row of its pass is one counted run without a mark and expires missing, visible (that day's pre-open pass did not run, intended); a re-run after `stop_time` that follows a partial pass is present. `Usable` and the old per-run `Returned` rule are gone. The values of Decision 4 stand: the evening bound never binds, the pre-open bound matters only for a start after the close.
- *Reconcile re-runs (S2).* A partial or crashed run runs again the same day and reads its rows first; a re-run respects `stop_time`, recounts `listed` from the table, never recomputes `expected` and writes a reason only when `listed` is below `expected`; a pass that listed something and hit its budget ends Err nil, is present through the Postcondition and is not re-run.
- *Run table in the interface and store entries (S1).* Adopted: `ListRunRecord` and four methods in entry 3, migration, grants and tests in entry 4; rows written at start as `not_finished`, `expected` is a list set once and null until known, `listed_pass` is on the list row, the evening writes the next session, no row is a gap, `list_max_new` is a reason.
- *Indexes.* Left out by name with the probe facts (the jobs' sources are US stocks only).
- *One-worker collisions.* The evening pass 16:30 to 18:00 can delay the ledger, the resolve and the JP plan by up to an hour (a delay, not a failure); the pre-open pass is done by 08:01 normally and bites the 08:00 jobs and the plan only on a late gateway, bounded by 08:30.
- *Earlier points, standing.* Gap against the goal: expiries pending the owner (Decision 8), `ListChains` at 5.0 s counted. Entry 1 is one owner-merged cut (contracts and pyside together); entries 2 and 3 touch no file of it. A simpler way (band-only, the existing gap): not adopted, no measured gap-pass duration exists and the owner asked for no dependence on yesterday; the new jobs touch nothing existing, so it stays as the fallback. Lock-in: `list_min_ratio`, "second short", `listed_session`, `listed_pass` and the run reasons are what B reads. The ratchet: `transport.py` at most 786 before formatting, stated after. The pyside restart is the owner's second step and the jobs say `list_unserved` until it.
