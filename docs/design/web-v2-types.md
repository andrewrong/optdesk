## What main holds today

- `contracts/schemas/page.market_summary.v2.json` and `page.options_summary.v2.json` exist (`schema_version` const 2, shared
  defs from `common.v1.json`, optional `stale_after`). The v1 files `page.market_summary.v1.json` and `page.options_summary.v1.json`
  stay, listed in `contracts/schemas/carryover.sha256`.
- Files of `web/` that read a v1 shape of these two schemas: none. `git grep -n -E 'market_summary|options_summary' -- web`
  finds nothing, and `git grep -n 'OptionsSummary' -- web` finds only the stub name `OptionsSummaryCard` in `web/test/shell/pages.test.tsx`
  (a module without a `registration`, which `discoverCards` skips). There is no `web/src/types/market_summary*.ts`, no
  `options_summary*.ts`, no card, no fixture directory for either schema. So the move is not a rewrite of readers: the two cards
  do not exist yet and are written against v2 from the start. The home card of the market today is `WeatherCard.tsx`, which reads
  the other schema `market_weather` v1 through `web/src/types/market_weather.ts`; it is not touched here.
- Where the TypeScript types come from today: `web/src/generated/index.ts` is a stub (`export {}`). Every file of
  `web/src/types/*.v1.types.ts` is a hand-placed copy from the old repository, and `web/src/types/placeholder.ts`
  (`placeholderValidate`) checks only that the payload is an object with a supported `schema_version`. All of these say
  "TEMPORARY hand-written placeholder". `web/src/generated/**` belongs to the row `contracts` and `web/package.json` to the row `web`.
- The only other readers of v1 text of the two schemas are in `contracts/`: `page.home_page.v1.json` holds the old Card defs of
  both (not a `$ref` to the summary files), which is why the v1 summary files cannot be deleted before a `home_page` v2.
- `contracts/generate.sh` is Go-only by its own header ("no npx"), and `.github/workflows/checks.yml` runs it in a job with Go and no node.
  `.github/workflows/ci-web.yml` runs `pnpm install --frozen-lockfile`, `tsc`, `eslint`, `vitest` and the build; it has no step that
  regenerates types and diffs. `.github` is owner-only.
- `internal/contracts/fixtures_test.go` maps each directory of `web/fixtures` to a schema (13 rows, v1 files through
  `compileCarried`), requires `bad-version.json` per row (13 entries, count checked) and fails on a directory without a row. The v2 files
  need `compilePageV2` (their `$id` is `https://optdesk.invalid/schemas/...`, refs to `common.v1.json` resolved by `dirLoader`).
- `web/src/shell/App.tsx` renders one page chosen by `payload.schema` through the `pages` registry; there is no home view-model that
  composes cards. A card is therefore shown only when a payload names its schema.
- No Go builder and no Python producer of either v2 page exists (`internal/pages` has `macro_page` and `macro_rates` only), so the
  cards below read fixtures, not a live page.

## Decisions

1. Types come from the schema: generated by `json-schema-to-typescript` 16.0.0 (MIT; the one designated generator of ADR 0034;
   whitelisted by issue #97). Our own generator is not written: a mainstream maintained library fits.
2. `contracts/generate.sh` stays Go-only. The TypeScript generation is the web script `generate:types` in `web/package.json`
   (a devDependency `json-schema-to-typescript` 16.0.0, no `^`). The script runs `json2ts` once per file with these flags pinned:
   `-i ../contracts/schemas/page.<name>.v2.json`, `-o src/generated/<name>.v2.ts`, `--cwd ../contracts/schemas` (so the relative
   `common.v1.json#/$defs/...` refs resolve from the schema directory, not from the `$id` host, which is `.invalid`), and
   `--bannerComment` set to two lines: `// Code generated from contracts/, DO NOT EDIT.` then `/* eslint-disable */`. The first line
   is the repository banner and says the file is generated from `contracts/` and must not be edited; the second keeps `eslint .` quiet
   on generated files. Prettier runs inside `json2ts` with its defaults, so the output is stable.
   The command from the repository root is `pnpm --dir web run generate:types`.
3. Drift check: `pnpm --dir web run generate:types && git diff --exit-code web/src/generated` belongs in `.github/workflows/ci-web.yml`,
   after `pnpm install`. That file has no such step and `.github` is owner-only, so the step is an owner change (`## Left out`); no
   issue edits `.github`. Until the owner adds it, nothing detects drift in the generated bodies: `TestGeneratedSummaryTypes` guards only the banner, the exported top-level names and the re-exports, and the acceptance greps check a few fixed strings.
4. Module of each path (docs/design/modules.md, first glob wins): `web/src/generated/**`, `internal/contracts/**` and
   `docs/contracts/page-schemas.md` are `contracts`; `web/package.json`, `pnpm-lock.yaml`, `web/deps-allowlist.txt`, `web/fixtures/**`,
   `web/src/**` (other than generated) and `web/test/**` are `web`. The cut has one interface issue and two cards. The interface issue
   carries a cross-module set that this design licenses (option (a) of the review): the generated files (`contracts`) together with
   the dependency, the lockfile, the allowlist and the script `generate:types` (`web`), and with `web/fixtures/**` (`web`). Reasons:
   (i) AGENTS.md says generated code is never edited by hand and that a change carries the source and the generated output together,
   and the script and the devDependency are the source of the two generated files, so they land in one pull request; (ii) the
   alternative (b), checked-in files without the generator and a Go-side drift check, would make the first version of the files
   hand-made and leave a drift check with nothing to regenerate from; (iii) with a separate generator issue the interface issue
   would be built only after a sibling merged, so the modules would not be buildable in parallel; (iv) `fixtures_test.go` fails on a
   fixture directory without a row and on a row without its `bad-version.json`, so rows and fixture files also land in one pull
   request. Nothing else edits files of two modules, and no issue edits `.github`.
5. Scope of generation: the two v2 schemas only. The other 20-odd `web/src/types/*.v1.types.ts` copies stay until their pages get a
   v2 file.
6. The `validate` function of a v2 page stays the placeholder check (`placeholderValidate` with `SUPPORTED_VERSIONS = [2]`) over the
   generated type. Ajv standalone validators are not on `frontend-whitelist.json`; fixture validity is instead checked offline by the
   Go test of `internal/contracts` (the existing `santhosh-tekuri/jsonschema` library, no new dependency).
7. v1 is retired by never being read: the cards import only v2 types, and an acceptance item greps that `web/` names no
   `market_summary.v1` or `options_summary.v1`. Deleting the v1 files waits for `home_page` v2 (`## Left out`). Under the version
   rule the v2 files freeze at their first consumer, and the cards below are that consumer.
8. The front end computes nothing: every text, tone, label and chart value is a field of the payload. The cards do not compare
   `stale_after` or `generated_at` with the clock.
9. Fixtures are invented data only, in the existing layout `web/fixtures/<name>/{ok,gap,stale,bad-version}.json` plus a README,
   listed in `web/fixtures/MANIFEST.synthetic-v1.json`.
10. Card registration is gated on payload presence by construction: `App` picks a page by `payload.schema`, and `discoverCards`
    registers the card under its schema name. A payload without `market_summary` never reaches `MarketSummaryCard`. No change of
    `web/src/shell/**` is needed and none is made.

## Interface

Owner: contracts (the entry of the row is `web/src/generated/index.ts`). Frozen by `generated-summary-types`, read by the two cards.

- `web/src/generated/market_summary.v2.ts` and `web/src/generated/options_summary.v2.ts`: one file per schema file, made by the
  script of Decision 2. The top-level type is named by the schema `title`: `MarketSummary`, `OptionsSummary`.
- Names of the inner types, read from the schemas at fe71bc3 (unchanged since 882a4db): `page.market_summary.v2.json` takes its `Gap` from
  `common.v1.json` (title `Gap`, the full reason list including `not_built`) and has no local `Gap`; `page.options_summary.v2.json`
  has a local `$defs/Gap` (title `Gap`, reasons `missing_quote`, `no_data`, `unsupported_currency`) and reaches no `Gap` of
  `common.v1.json` (its `UsdFigure` and `UsdSignedFigure` carry none). So each file holds exactly one interface named `Gap`, and the
  two differ in shape. No `Gap1` is expected inside a file; the collision is between the two files, which is why `index.ts` does not
  re-export inner types. A page reaches them as `MarketSummary['card']`; a card may alias one locally.
- `web/src/generated/index.ts` re-exports exactly two names: `export type { MarketSummary } from './market_summary.v2'` and
  `export type { OptionsSummary } from './options_summary.v2'`, with the banner.
- (interface) entry: `web/src/generated/index.ts`.

## Adversarial

Full answer: the dispatcher scratchpad file `web-v2-types.adversarial.md` (not in the repository; the path is left out because it holds a local user name).

1. Gap (fixtures_test.go count and rows; `checks.yml` runs generate.sh without node): adopted. `fixtures_test.go` joins the interface
   issue with rows, 15 bad-version entries and `compilePageV2` (`compileCarried` cannot load v2 files); the fixtures move into that
   issue so rows and files land together; `generate.sh` stays Go-only so `checks.yml` is unaffected.
2. Biggest unnamed risk (no node regeneration in CI): adopted. Generation is the web script `generate:types`; the drift step belongs in
   `ci-web.yml`, which lacks it; named in `## Left out` as an owner change.
3. Simpler way (drift check in ci-web, merge dependency and generation): adopted for the CI move and for merging the dependency with the
   script. The first revision kept the generated files in a second issue; the design review made that wrong (see Review below), and the
   generator now lands with its output.
4. Lock-in (v2 freeze at first consumer; inner types by indexing): not adopted as a change. The freeze is the version rule, and
   re-exporting inner types would collide on `Gap` between the two files. A card may alias `MarketSummary['card']` locally.
5. Most likely false claim (banner, `$ref` resolution, `Gap`/`Gap1`): adopted. The flags are pinned (`--bannerComment`, `--cwd`, outputs)
   and acceptance 3 of the interface issue checks the names by grep. From the schemas each file has one `Gap` and no `Gap1`; the
   behaviour of `json2ts` itself is unverified until the script runs.
6. Likeliest slip (a card cannot pass ci-go without editing a contracts file): adopted, same fix as point 1; the cards no longer
   touch fixtures or the manifest.
