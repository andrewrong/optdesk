## What main holds today

## Decisions

1. Port unchanged, version 2. Register id `macro.ease`, `version = 2` (the number of option-trader's version; optdesk has no version 1, and the retired version 1 is not ported). Display only: nothing votes, offers, sizes or gates on it. Scale 0 (tightening) to 100 (easing). Four inputs, equal weight, each a linear sub-score between two fixed points and clipped to 0..100 (`100 * (figure - at_0) / (at_100 - at_0)`):
   - `net_liquidity`: the change of weekly net liquidity (Decision 3), a fraction; +0.03 is 100, -0.03 is 0; may be 10 calendar days old.
   - `us10y`: `DGS10` today minus `DGS10` 63 observations earlier, in basis points (percent x 100); -75 is 100, +75 is 0; may be 3 weekdays old.
   - `fed_funds`: `DFF` on a session minus `DFF` on the session 126 sessions earlier, in basis points, sessions being the observation dates of `SP500`; -50 is 100, +50 is 0; may be 7 calendar days old.
   - `hy_oas`: `BAMLH0A0HYM2`, percent, newest point; 2.5 is 100, 5.5 is 0; may be 3 weekdays old.
   The value is the mean of the sub-scores present (not the rounded ones), rounded half-even to 2 places; it has no value with fewer than 3 present (min_inputs 3); a missing input is one that is absent, short (fewer observations than its window) or older than its age. "Weekdays old" counts Monday to Friday after the data day through the as-of day, no holidays (`weekdays_after`). The band is taken on the value after the 2-place rounding, rounded half-up to a whole number: 0..33 tighter, 34..66 steady, 67..100 looser. All arithmetic is exact rationals (`math/big.Rat`), each float64 input first turned into its shortest decimal text (`strconv.FormatFloat(v, 'g', -1, 64)`) so that 3.23 is 3.23 and not its binary neighbour; option-trader does the same with `Fraction(Decimal)`. Own implementation, because no library does a clipped linear scale of several inputs and it is stdlib arithmetic; it sits behind the interface `compute.Ease` (owner's rule) so a library can replace it.
2. Weekly alignment, ported unchanged. Weekly net liquidity of a Wednesday W is `WALCL(W) - WDTGAL(W) - RRP`, where `RRP` is the newest `RRPONTSYD` point in the week (W-7, W] (the series is daily; a week with none has no figure). A Wednesday has a figure only when both `WALCL` and `WDTGAL` have a point dated exactly W (a point dated another weekday is not used). The change at W is the sum of the figures of W, W-7, W-14, W-21 divided by the sum of the figures of W-91, W-98, W-105, W-112 (13 weeks back, same four weeks), minus 1; so it needs 17 consecutive Wednesdays with figures, and none when any of the eight weeks is missing or the earlier sum is 0 (the two means are of equal counts, so the ratio of sums is the ratio of means). The figure of the as-of day is the newest Wednesday on or before it that has a change (an older one is then judged by the 10-day age: a Wednesday more than 10 days old makes the input stale). `us10y` and `fed_funds` take the newest observation, or session, on or before the as-of day that has a figure; a session whose `DFF`, or whose earlier session's `DFF`, is missing has no figure and the newest earlier one is used. A no-value point (FRED's dot) is not an observation: it is not counted in the 63 or the 126.
3. Units of the liquidity series: the source normalises to whole dollars. `seriesUnits` becomes a table of `{unit, currency, shift}`: `WALCL` and `WDTGAL` are `ccy_amount`, `USD`, decimal point shifted 6 places right (FRED states "Millions of U.S. Dollars"); `RRPONTSYD` `ccy_amount`, `USD`, shifted 9 ("Billions of U.S. Dollars"); `DFF` and `BAMLH0A0HYM2` `percent` (shift 0, "Percent"). The shift is made on the decimal text of the FRED value before it becomes a float64 (so `0.123` billions is `123000000`, with no float error), and the mapper sets `Currency` for every `ccy_amount` row. `mapping_test.go` learns the full recorded text of a `ccy_amount` series: the recorded text must be exactly "Millions of U.S. Dollars" with shift 6 or "Billions of U.S. Dollars" with shift 9, else the test fails. Weekly net liquidity is then `WALCL - WDTGAL - RRP` in dollars, which is option-trader's figure x 10^9; the change is a ratio, so it is the same number. No contract changes: `ccy_amount` and `currency` exist. Rejected: new unit words `usd_millions` and `usd_billions` (a second additive change to `series_unit`, a migration, and every reader then converts), and storing FRED's raw magnitude with the factor in code (the stored point would not say what it is).
4. Loading the weekly and late series: the fred_series manifest gets a `lookback_days` table. For an id in it the run fetches `[day - N, day]` instead of `[day, day]`: `WALCL` 14, `WDTGAL` 14, `RRPONTSYD` 7, `DFF` 7, `BAMLH0A0HYM2` 7. The Thursday release then reaches the run of the next session day (and, with 14, of the one after a missed week). The writer is idempotent on `(series_id, observation_date, realtime_start)`, so a repeated fetch inserts nothing new. The seven series already loaded keep a window of the day itself. The ids in the table must be in `series`, and N is 1 to 31. The plan hash (`plan()`) includes the table, sorted, so a change of a window is a new plan. Not verified here: that FRED returns these values by the Friday 07:30 run (no live call is allowed); if a value arrives later, the figure is missing with `stale_input` until it does, which is the stored behaviour the page shows as a gap.
5. History: the score needs 17 weeks of `WALCL`, `WDTGAL`; 63 `DGS10` observations; 127 `SP500` sessions with `DFF`; `RRPONTSYD` for the same 17 weeks; so about 270 calendar days. The owner loads at least one year of the five new ids with `ot series-load --series ID --from DAY --to DAY` (`compute-fred-series.md` Decision 3; the owner's word is needed before the window runs it). Until then the figure is missing with `short_history` parts. The job's lookback for the series it reads is `2 * window + 14` days of `lookbackDays` with `window` 126 in `rules.json`: 266 days, enough for 126 sessions (about 183 days), 63 observations (about 95 days) and 17 weeks (119 days) with a margin of at least 40 percent for holidays.
6. Register and hash. One new entry, `macro.ease` version 2, in `docs/conventions/register.toml` (15 keys, `pages = ["macro_page.ease"]`, the glossary words of the issue `ease-register`), `currency` "Unit decimal, stored as decimal text, rounded half-even to 2 places." (the sentence `TestRulesMatchRegister` expects), `implemented_by` the functions of package `internal/compute/ease` that hold the rule: `internal/compute/ease.(*calc).Ease`, `internal/compute/ease.params`, `internal/compute/ease.score`, `internal/compute/ease.netLiquidityChange`, `internal/compute/ease.weeklyNetLiquidity`, `internal/compute/ease.changeBack`, `internal/compute/ease.fedFundsChange`, `internal/compute/ease.band`. The fixed points, the ages and the band edges are written in the body of the function `params`, not in a data file, so the existing hash (sha256 of the normalised source of the listed functions, then the canonical JSON of the rule's numbers) covers them without a change to `rules_test.go`: a change of a fixed point changes the hash and fails `TestHashesMatchSource` until the register entry is updated with the advisor's agreement. `rules.json` gains `{"id":"macro.ease","version":2,"convention":"ease_v2","unit":"decimal","scale":2,"window":126,"min_valid":3,"max_age_days":10}` (the other keys zero, `hash` real): `window` is the session lookback of `lookbackDays`, `min_valid` is min_inputs, `max_age_days` is the largest of the four ages and is only a bound (the age of each input is in `params`). The readings of `macro.ease` are stored by `compute_figures` with the rule hash in `reading_input.code_version` like every figure. Only the score is registered; `macro.net_liquidity_13w` and the two basis-point changes are statistics inside it, hashed through it (see Left out).
7. Stored form, by the pattern of `compute-figures.md` Decisions 2, 3 and 9. `name` `macro.ease`, `version` 2, `subject_kind` `market`, `subject` `WALCL` (the FRED id of the first input, as Decision 9 says), `unit` `decimal`, `value` the text of the half-even rounding at 2 places; `Figure.DataDay` is the newest data day among the inputs used and `Observations` the number of inputs used. `parameters`: `band` (`value_tag` `tighter`, `steady` or `looser`; absent when the value is missing) and, per input name, `<input>.data_day` (tag, ISO day), `<input>.figure` and `<input>.score` (numbers) for an input present, `<input>.reason` (tag, one of the five reasons) for one missing. A value missing for fewer than 3 inputs is state `missing_input` with `reason_code` 1 (`no_input`: option-trader's single reason `too_few_inputs`); the reason of each missing input is in its own parameter. The inputs row is `obs.series_point` with the seven FRED ids as keys.
8. The page. `macro_page.Config` gains an optional `Read compute.ReadingFunc`; nil keeps today's gap and the existing tests. With it, `Build` reads `macro.ease` v2, `market`, `WALCL` for the day, and for the day 7 calendar days before. A winner reading with a value gives: `figure` (value to 1 decimal half up, text the whole number half up), `marker_percent` (value to 2 decimals, text the whole number), `neutral_band` `low` 34 and `high` 66 as `percent_of_track` with texts `34%` and `66%` (the numbers of `macro-summary/ok.json`; the edges of the band on the value are 33.5 and 66.5, the track draws the whole numbers that name the band), `ticks` `0 25 50 75 100`, `week_change` the difference of the two values as an `IndexPointsFigure` when the earlier day has a value (text with the sign, `+1.2` or `−0.2` with U+2212, as the fixtures), else a `Gap` `no_data` `较上周暂无数据`, `reading_text` and `aria_text` in the wording of `macro-summary/ok.json` with the band word of the stored `band` (tighter `偏紧`, steady `中性` as in the fixtures, looser `偏松`; text of the page, not of the register). A missing or absent reading keeps the `no_data` gap (`松紧度暂无数据`), and the page data time of `macro_ease` is the reading's `data_day`. `cmd/ot` opens no readings reader for `macro_page` on main: that wiring belongs to the wire of `compute-figures.md` (`compute-jobs-wire`) and is not cut here (Left out).

## Left out

Registering it is one more `[[figure]]` and one more job key; it is added when a page cites it by id and version. Not a deferral of the score: the score is complete without it.
- The version 1 of the score (retired in option-trader, different HY OAS points) and a `macro.tbill_3m_change_63` reading: neither feeds version 2.
- The wiring of `macro_page.Config.Read` in `cmd/ot`: `cmd/ot` has no readings reader on main (`OT_PG_DSN_READINGS` is opened only by the wire of `compute-figures.md`, not cut yet), so an `ot` issue here would invent that wiring ahead of its design. Until it lands the page shows the gap with `Read` nil, as today. This is a dependency, named.
- Storing the figure in FRED's own magnitude with new unit words (`usd_millions`, `usd_billions`): rejected in Decision 3, it adds a second change to `series_unit` and a migration and makes every reader convert.
- Keeping the daily fetch of a single day for the weekly series: rejected in Decision 4, the Thursday release comes after the 07:30 slot, so the Wednesday value would only be read if some later run asked for that day; a window that repeats a fetch costs nothing (the writer is idempotent).
- A data file for the fixed points (`ease_v2.toml` as in option-trader) read at run time: rejected, the hash discipline covers function source and the canonical numbers of `rules.json`; numbers in a file the hash does not read would change a score without a hash change. They are in the body of `params`.
- Putting the score in `compute.Figures` as an eighth method: rejected, it changes an interface that the golden suite `contracttest` runs and every fake of it; a separate small interface changes nothing that exists.
- Making `ease` a method of `internal/compute/figures`: rejected, that package may import only `contracts` and `compute` and holds the stats-based figures; the score has no use of `Stats` or `Rolling`, and its own package keeps its hash set small.
- A holiday calendar for "weekdays old": option-trader counts Monday to Friday and the port keeps it; a holiday can make an input count one weekday older than a trading calendar would, which only turns a figure missing one day earlier. Changing it would be a version 3.
- A change of the fixed points, windows or labels: the score is ported unchanged; a change is a new register version with the advisor's agreement.

The page words `偏紧` and `偏松` are the designer's choice beside the fixtures' `中性`; they are page text and one line each to change.
