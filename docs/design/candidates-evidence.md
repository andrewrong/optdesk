## Goal

The page answers "which strike, and why" with the figures the plan names for step 9, and says where a figure is missing and why. Nothing on the page is computed by the page: the `Evaluator` of `optionevidence` gives every figure, including every percent (the times-100 step is in compute), the stored readings give the name-level values, the existing figure columns stay.

## Today

- `optionevidence` is a pure function of one row: `Evaluate(Row) (Evidence, error)`. `Evidence.OneSigmaPct` and `Evidence.BelowBuyPct` are already percents (fraction times 100, four decimals, `evidence.go`); `Skew` is a fraction difference of two IVs, `Forecast` and `ForecastErr` are fractions, and nothing in compute turns them into percents. It takes the ATM IV and ATM strike of the same expiry as input but nothing in compute picks them (`internal/compute/optionevidenceapi/api.go`, `Row.ATMIV`, `Row.ATMStrike`). It has no rate age check: `Row.RatePercent` is used as given.
- The candidates page has the three kinds of rows as groups; the short-put group has 15 columns, two of them from `optionfig` through `Config.Figures` (`figcells.go`). Column ids are free text of the schema (`common.v2.json#/$defs/Id`) and a cell is a `ValueCell` or a `Gap`, so a column is added with no schema change; the figures design did the same (`docs/design/option-candidates-figures.md`). Texts (`Text`, hint, badge, note) are at most 200 characters.
- The web page renders the columns by id from the payload (`web/src/pages/candidates/CandidateGroup.tsx`, `GroupTable`), so a new column needs no web change; a column hint shows as a header tooltip and a badge as a line under the cell.
- The name-level readings `market.vol_forecast`, `market.vol_forecast_err`, `market.ivp_ibkr` and `market.vol_edge` are stored (decimal text, fractions) and shown on the single-name option page (`internal/pages/option_boards/stock_vol.go`) with a read of 7 days before the day; the candidates page reads none of them.
- The chain of the group day is in `obs.option_day`: `optionday.DayReader.ChainDay(ctx, underlyingID, day)` gives rows with the IV and a `Source` by instrument id and no strike or expiry; `store.OptionTermsReader.OptionTerms` gives right, strike and expiry for at most 500 ids per call.
- The `Source` values of `obs.option_day` are `option_eod` and `option_open` (`internal/store/optionday/api.go`). A stored candidate has no source column; its bid is `BidEod` and the rows are made from the `option_eod` capture (`docs/design/option-candidates.md`, Today), so the capture of a candidate's own quote is `option_eod`, and that is the Source the ATM row must have.

## Decisions

1. **Columns only, no schema change, no web change.** The short-put main table gains the columns `below_buy`, `one_sigma`, `bid_vs_forecast`, `skew`, `forecast_vol`, `ivp`, `vol_edge` and `labels` (eight) after the stored ones, in this order. `contracts/schemas/page.option_candidates_page.v1.json` is unchanged (`Contracts: unchanged`). There is no web issue: `GroupTable` renders any column. A table of 23 columns is not tested in web by this design (no web module is edited); see Left out. The screenshot check of the rendered page against the sample above is done by the window after the merge and is not an issue.
2. **Every figure comes from the `Evaluator` or from a stored reading; the page only places text and never computes.** The page builds one `optionevidenceapi.Row` per ok row from the stored candidate (`ChainDay` = the group day, `Expiry`, `ExDiv` = `NextExDate`, `DTE`, `Spot`, `Strike`, `Bid` = `BidEod`, `BuyPrice`, `IV` = `Iv`, `Delta`, `Multiplier`, all as stored text), the cash rate (Decision 8), the readings (Decision 11) and the ATM pair of `Config.ATMFor` (Decision 12); it calls `Evaluator.Evaluate` once per row and writes the cells from the answer. `Row.EarningsBeforeExpiry` is not set by the page: an ok row never has an earnings block, because the events gate blocks the row (`docs/design/option-candidates.md`, the events gate) and the stored gate result of an ok row never holds `earnings_before_expiry`; the plan's "no edge for earnings inside the life" is delivered by that block, not by this page. The order of rows and of columns is the stored order; the page sorts nothing and computes no total, rank or score.
3. **Which rows.** Evidence is shown for the ok rows of the short-put group (its main table). The blocked and unknown rows of the second table keep their reasons and get no evidence column; covered calls and held call guards are unchanged. The merged design `docs/design/candidate-evidence.md` says the compute also runs for blocked rows; this page does not show them, and plan step 11 (the order of companies) may reopen it.
4. **Units: where the times-100 happens.** Compute does it, the page never. A figure is either a fraction (the stored or input form, 0.294 for 29.4%) or a percent (the fraction times 100 at four decimals, 29.4000); the page only rounds a percent text to one decimal with the existing `fixedText(text, 1)` and appends `%` or ` pts`; it does not call `percentText` or `roundDigits` with a shift for any evidence figure. The table:

   | figure | input | compute output | shown as |
   |---|---|---|---|
   | below buy | money | `BelowBuy` money, `BelowBuyPct` percent | `$0.94 (1.0%)` |
   | one-sigma | IV fraction | `OneSigma` money, `OneSigmaPct` percent | `$8.58 (8.9%)` |
   | sigma to break-even | none | `BreakEvenInSigmas` plain number | `0.9 sigma to break-even` |
   | bid vs forecast | money, forecast fraction | `EdgePerShare`, `EdgePerContract`, `Fair` money | `+$0.21 per share (+$21.29 per contract)`, `model price $0.73` |
   | skew | two IV fractions | `SkewPct` percent (new), in percentage points | `+1.1 pts` |
   | ATM IV | IV fraction | `ATMIVPct` percent (new) | `ATM IV 29.4% at 95.00` |
   | forecast vol | fraction | `ForecastPct` percent (new) | `27.5%` |
   | last error | fraction | `ForecastErrPct` percent (new) | `last error 4.1%` |
   | IV percentile | fraction | `IVPPct` percent (new) | `58.0%` |
   | name IV vs forecast | fraction | `VolEdgePct` percent (new), in percentage points | `+3.7 pts` |

   The new fields are filled by `Evaluate` from `Row.IV`, `Row.ATMIV`, `Row.Forecast`, `Row.ForecastErr` and two new `Row` inputs `IVP` and `VolEdge` (fractions, "" when none); each percent field is the input times 100 at four decimals, empty when its input is empty or not a number.
5. **Number text.** Money is text as `$`, thousands separators and two decimals, rounded half away from zero, with the minus sign U+2212; a percent has one decimal; the page never adds, subtracts, multiplies or divides a figure. A signed amount ("Bid vs forecast price", "Skew", "Name IV vs forecast") has a leading `+` when it is not zero and not negative, decided on its text, and U+2212 when it is negative. The sort value of a cell is the figure's decimal text as `figValueCell` writes it.
6. **Words, glosses and data days.** The column labels are `Below buy`, `One-sigma move`, `Bid vs forecast price`, `Skew`, `Forecast vol`, `IVP`, `Name IV vs forecast` and `Labels`; the column hints carry the glosses of the sample. The compute contract names the edge "bid vs forecast price", never "edge" or "advantage" (`docs/contracts/compute/optionevidence.md`). Every hint is at most 200 characters and names the data day of its figures: the group's chain day for `below_buy`, `one_sigma`, `skew` and `labels`, the chain day and the cash-rate day for `bid_vs_forecast`, and, for the three reading columns, the words "data day in the badge" while each reading cell carries the badge `as of <data day>`. The hint of `bid_vs_forecast` is, word for word, with the two days filled in (the day format has ten characters, so the length does not change): `Bid minus a model price from the forecast vol (a proxy, sign often wrong; European, no dividends). DGS3MO is the cash rate for every currency (a trial). Data days: chain 2026-11-17, rate 2026-11-16`. It has 197 characters, the longest hint of the page, and ends with its data days; the trial sentence `DGS3MO is the cash rate for every currency (a trial).` stands before them. The cell also carries the badge `as of <forecast day>` of Decision 11 when the forecast day differs from the chain day; the badge is not part of the hint.
7. **One-sigma.** The page shows `OneSigma` as money, `OneSigmaPct` with one decimal and `BreakEvenInSigmas` as a badge with one decimal and the words "sigma to break-even", all read from `Evidence`; the formula stays in compute (`OneSigma` = spot x IV x sqrt(DTE / `Params.DaysInYear`), 365 by `DefaultParams()`); the page passes DTE and writes no 365.
8. **Cash rate age.** The cash rate of an evidence cell is the page's existing DGS3MO read, passed to the `Evaluator` only when its day is at most 7 days before the group day (the constant `maxRateAgeDays` of `figcells.go`, equal to `max_rate_age_days` of `job.toml`); the setting is not read, so the two figures of one row (the optionfig input and this one) use one constant. A rate older than that is passed as empty, which `optionevidence` answers with `no_rate`. A settings reader is in Left out.
9. **Trial rate.** The cash rate is DGS3MO for every currency: a trial, said on the page twice: in one line of `notes`, `The cash rate used for the bid vs forecast price is DGS3MO for every currency; this is a trial.`, and as the sentence `DGS3MO is the cash rate for every currency (a trial).` inside the hint of the column Bid vs forecast price, placed before the data days that end that hint (Decision 6 gives the hint word for word).
10. **Empty IBKR value.** An empty value that IBKR supplies (Delta, contract IV) is shown as `not stored` in the evidence cells, never as 0 and never as a blank; the stored Delta and IV columns keep their dash. The `One-sigma move` and `Skew` cells of a row with no stored contract IV are gaps with the text `not stored` (`no_iv`), and the `Labels` cell of a row with no stored Delta carries the text `delta not stored`; no label `delta_outside_band` is written for it.
11. **Name-level readings.** The page reads `market.vol_forecast`, `market.vol_forecast_err`, `market.ivp_ibkr` and `market.vol_edge` with `Config.Readings.WinnerReadings(ctx, name, "underlying", subject, from, day)` where `subject` is the ticker of the row (`Config.Names`, by the underlying id), `day` the group day and `from` 7 days before it by the package's `daysBack`. It takes the newest reading whose state is ok and that has a value, and passes its text as `Row.Forecast`, `Row.ForecastErr`, `Row.IVP` or `Row.VolEdge`; the cell carries the badge `as of <data day>` of that reading. The Bid vs forecast price cell carries the same badge `as of <forecast day>`, the day of the `market.vol_forecast` reading, when that day differs from the group day (compared as day text, no date arithmetic); with the same day it has no such badge. With no ok reading the cell is a gap with the reason word of the newest stored missing reading (`no_input`, `short_history`, `stale_input`, `zero_range`, `bad_input`, as the single-name page names them), `no_input` when there is none. With a nil `Config.Names` there is no ticker and the page falls back to a gap, not to the stored issuer text: the three reading cells are the gap `no_reader` with the text `No ticker: readings are by ticker`, and Bid vs forecast price is the gap `no_forecast` as the `Evaluator` answers it for an empty forecast; a nil `Config.Readings` gives the same gaps with the text `No reading reader`.
12. **The at-the-money row.** The rule, word for word: puts only, same Source as the candidate's own stored quote (`option_eod`; the other value of the store is `option_open`), IV above 0, the strike nearest to spot within 10% of spot (a trial value of this design), the lower strike on a tie; none gives the gap `no ATM quote`. The compute picker `ATMPicker` (entry 1) implements it on a list of `ChainQuote`. The page does not read the chain and does not join anything: `Config` gets one function field `ATMFor` (entry 2), `func(ctx, underlyingID int, day, expiry contracts.Day, spot string) (iv, strike string, err error)`, and the page calls it once per ok row with the row's underlying, group day, expiry and spot, copying its two texts into `Row.ATMIV` and `Row.ATMStrike`; empty texts make the `Evaluator` answer `no_atm`, and the skew cell is the gap text `no ATM quote` (reason `no_data`). `cmd/ot` fills `ATMFor` (Decision 16): it reads `ChainDay` once per underlying and day, reads the terms of the chain's instrument ids in chunks of 500, builds one `ChainQuote` per row that has terms (expiry, right, strike, IV and Source copied as text), and calls the picker with Source `option_eod`. The reason for puts only and the same Source: the candidate is a put from the end-of-day capture, so the skew compares like with like; the 10% band keeps a far strike from being called "at the money".
13. **Cost per request.** The page is built per request. Per underlying that is one `ChainDay`, `ceil(chain rows / 500)` calls of `OptionTerms` (the closure of `ATMFor` keeps the joined chain per underlying and day for the life of the request) and four reading reads. A reader error is an error of `Build`.
14. **Labels.** The `Labels` cell lists, as badges, the labels of `Evidence.Labels` in their order: `no_edge_at_bid` as "bid not above the forecast price", `delta_outside_band` as "delta outside the trial band", `ex_div_inside_life` as "ex-dividend inside the life"; none gives the dash. A label never changes whether a row passes a gate, which row is shown or where. The band and the other trial values stay in `DefaultParams` and are not written on the page.
15. **Gaps and reasons.** An empty figure of the `Evaluator` becomes a `Gap` cell whose text is by its `Why` code: `no_buy_price` "No buy price set", `no_iv` "not stored", `no_forecast` "No forecast volatility stored" followed by the reading's reason word of Decision 11 in brackets, `no_rate` "No cash rate within 7 days (DGS3MO)", `no_fair_price` "The model price could not be made", `no_atm` "no ATM quote"; the gap reason is `no_data` for these, `missing_input` for `no_iv` and `no_forecast`. A candidate row with no stored spot gets every evidence cell as a gap with the text `no spot` and the reason `no_data`: the page builder (`evidence.go`, entry 3) chooses it by testing the stored spot text for empty before building the `Row`, calls neither `ATMFor` nor `Evaluate` for it, and compute is not asked; it is text placement, not a computation. A code the page has no text for (`zero_dte`, which a page row cannot have because the minimum DTE is 21, and `earnings_before_expiry`, which Decision 2 explains) is the gap `unreadable`. A nil `Evaluator` gives every evidence cell the gap `no_reader`; a nil `ATMFor` gives the skew cell the gap `no_reader`. An `ErrBadInput` of `Evaluate` (`errors.Is`) gives that row's evidence cells the gap `unreadable`; any other error, and any reader error, is returned by `Build`.
16. **Wiring in its own file.** `cmd/ot` builds the page with `Evidence` = `optionevidence.New(bsm.New(), optionevidence.DefaultParams())`, `ATMFor` from the picker `optionevidence.NewATMPicker()`, `rd.days` and `rd.terms`, and `Readings` = `rd.view`. The constructor `newOptionCandidatesPage` moves out of `wire.go` into the new file `cmd/ot/evidence_site.go`, which also holds the `ATMFor` closure and the imports of `optionevidence` and `bsm`; `wire.go` loses the function (7 lines) and the `optionfig` import (1 line) and gains none, so it ends below today's 781 lines and the limit 800. The page `ot page --name option_candidates_page` opens the candidate and name stores as today and passes no evidence readers, so there the evidence cells are the gap `no_reader`; the served route is the live path.
17. **Trial values.** The 10% band of Decision 12, the rate DGS3MO for every currency (Decision 9) and the 7 days of Decision 8 are trial values; the owner sets them after seeing the page. The band is a constant of the picker named in the compute contract doc.

## Interface

Entry 1 (module compute, `internal/compute/optionevidenceapi/api.go`, declarations added, no existing line changed):

    // ChainQuote is one listed option of the chain of one underlying on one day: its expiry, its right
    // ("P" or "C", as the terms store it), its strike and its implied volatility as decimal text (empty
    // when the row has none), and the Source of the quote ("option_eod" or "option_open").
    type ChainQuote struct {
        Expiry contracts.Day
        Right  string
        Strike string
        IV     string
        Source string
    }

    // ATMPicker chooses the at-the-money row of one expiry. Among the rows of expiry whose Right is "P",
    // whose Source is source and whose IV is a number above 0, it takes the strike nearest to spot within
    // 10% of spot (a trial value), the lower strike on a tie, and returns that row's IV and strike; with no
    // such row, or a spot that is not a number above 0, both are empty. It writes nothing and reads no clock.
    type ATMPicker interface {
        ATM(chain []ChainQuote, expiry contracts.Day, spot, source string) (iv, strike string)
    }

`Row` gains `IVP` and `VolEdge` (name-level fractions, "" when none). `Evidence` gains `SkewPct`, `ATMIVPct`, `ForecastPct`, `ForecastErrPct`, `IVPPct` and `VolEdgePct`: each is its fraction input (`Skew`, `Row.ATMIV`, `Row.Forecast`, `Row.ForecastErr`, `Row.IVP`, `Row.VolEdge`) times 100 at four decimals, "" when the input is empty or not a number. In package `optionevidence`: `func NewATMPicker() optionevidenceapi.ATMPicker`.

Entry 2 (module pages, `internal/pages/option_candidates_page/page.go`, the interface entry of the page): `Config` gains the fields `Evidence optionevidenceapi.Evaluator`, `ATMFor ATMFunc`, `Readings store.ReadingViewReader`, declared with `type ATMFunc func(ctx context.Context, underlyingID int, day, expiry contracts.Day, spot string) (iv, strike string, err error)`, each documented as "nil gives the gap no_reader"; `NewPage` and `Build` are unchanged until entry 3 uses the fields. The existing fields keep their names and meaning.
