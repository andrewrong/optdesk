## Brief

Background. The Go side (the option_eod freeze and the index IV job of weeks 3-4) cannot talk to IB Gateway directly. The plan puts a small Python service, `pyside`, between IB Gateway and Go,
speaking gRPC over `contracts/proto/ibkr/v1`. Today only the probe `Ping` exists. The service is a new outside system (a socket to the owner's gateway session, a listening socket, two new
network libraries), so this is a second-opinion case. Decided and not reopened: the libraries (owner, 2026-11-06), the connection, guard and pacing rules of ADR 0003 with its amendments, and the
plan's lock that the listener is a Unix socket under `$OT_HOME`. This cut alone does not give the jobs their data: the Go client (`internal/broker`, a design of its own) is the blocking item for the W3-4 jobs.

Proposal.

1. Proto v1 grows two services beside `SessionService`: `ContractsService` (`ListChains`, `ResolveContract`) and `MarketDataService` (`Snapshot`, server streaming). Every contract in a request carries its conId.
   A request kind is named by purpose (`OPTION_EOD`, `UNDERLYING_IV`) and its specification (tick list, wanted fields, timeout) is written in the proto comment and held in one table in pyside. The market-data type is a
   session setting, set once per session by pyside, not a request field. No account, position or order message and no order rpc exists.
2. One asyncio loop: `asyncio.run(main())`, a `grpc.aio` server, ib_async through its `*Async` methods and `Client.connectAsync`. Forbidden and checked by grep and by an AST test: `util.startLoop`, `util.patchAsyncio`,
   `ib.run`, `ib.sleep`, `IB.connect`, `IB.connectAsync`, every sync request wrapper of `IB`, and `nest_asyncio` (neither imported by our code nor applied at run time).
3. The connection follows ADR 0003: an `IB` object is built, a guard is installed on its `client` (`send` and `sendMsg`) before `Client.connectAsync`, which refuses the order message ids and everything not on an allowlist; then the market-data type is set. The guard lives
   in `transport.py`, which is owner-only, so a worker cannot loosen it without the owner's merge. Only one file imports `ib_async`.
4. Pacing and the request specification live in pyside only, over a `Clock` (a fake in tests; no test sleeps): the ADR's 40 starts per second, 50 snapshots in flight, 70 lines, and the adaptive contract-detail lane of 1 to 5 requests.
5. Account ids reach memory (the library holds them) and DEBUG logs of ib_async. Our code never logs, stores or sends them: a field whitelist on our log records, a scrub of free text, and the `ib_async` logger set above DEBUG, each with a test.
6. The server listens on a Unix socket `$OT_HOME/run/ibkr.sock`, directory mode 0700, socket mode 0600; no TCP, no TLS, no token.
7. Five issues (below) after the two named dependencies of the design pyside-calendar. The version freeze of `ibkr.v1` is accepted with its cost (`## Adversarial`, point 4).

3. Is `QuoteStatus` plus the IBKR error code, and the error text only on error statuses, the right level for Go to decide on?

5. Python generation by `grpc_tools.protoc` through its own script, not in `generate.sh`, with an offline freshness test: enough?

Owning module: `contracts` (the proto files and the Python entry file that re-exports their output). `pyside/src/optdesk/ibkr/api.py` of `pyside` stays as it is (`## Left out`).

Naming: `buf lint` with `STANDARD` requires the suffix `Service`, so the services are `SessionService` (exists), `ContractsService` and `MarketDataService`; requests and responses are `<Rpc>Request` and `<Rpc>Response`; enum values carry the enum
name as prefix and the zero value is `_UNSPECIFIED`. All three files use package `ibkr.v1` and the `go_package` option of `session.proto`. The version is amended in place (`ibkr.v1` has no consumer yet); the first generated import, in `transport.py`, freezes it.
Comments in the proto files avoid the words the acceptance greps look for (the three words of `ibkr-proto` item 3).

`session.proto` (amended): `PingResponse` keeps `bool connected = 1;` and gains `int64 generation = 2;` (0 before the first connect, plus one at each reconnect; quotes of two generations are from two sessions) and
`MarketDataType market_data_type = 3;` (the type set on the current session; the enum is in `marketdata.proto`, so `session.proto` imports it).

`contracts.proto`:

```
enum SecType { SEC_TYPE_UNSPECIFIED = 0; SEC_TYPE_STOCK = 1; SEC_TYPE_INDEX = 2; SEC_TYPE_OPTION = 3; }
enum Right { RIGHT_UNSPECIFIED = 0; RIGHT_PUT = 1; RIGHT_CALL = 2; }
enum ResolveStatus { RESOLVE_STATUS_UNSPECIFIED = 0; RESOLVE_STATUS_FOUND = 1; RESOLVE_STATUS_NOT_LISTED = 2; }

message ContractSpec {          // a fully specified contract; an option leaves nothing open
  SecType sec_type = 1;
  string symbol = 2;
  string exchange = 3;
  string currency = 4;
  string expiry = 5;            // YYYYMMDD, options only
  string strike = 6;            // canonical decimal text, options only
  Right right = 7;
  string multiplier = 8;
  string trading_class = 9;
  int64 con_id = 10;            // required by Snapshot (zero is INVALID_ARGUMENT); answered by ResolveContract
}

service ContractsService {
  rpc ListChains(ListChainsRequest) returns (ListChainsResponse);
  rpc ResolveContract(ResolveContractRequest) returns (ResolveContractResponse);
}
message ListChainsRequest { ContractSpec underlying = 1; }            // a stock or index with its con_id
// strikes is the union over all expirations of the chain, not the strikes of each expiration: most pairs of an
// expiration and a strike do not exist (one run asked 8,170 and all came back not listed). The caller resolves
// only the pairs it needs, and keeps a not-listed answer for days (the 7 days plus jitter of ADR 0003); this service keeps no cache.
message ListChainsResponse { int64 underlying_con_id = 1; repeated Chain chains = 2; }
message Chain { string exchange = 1; string trading_class = 2; string multiplier = 3; repeated string expirations = 4; repeated string strikes = 5; }
message ResolveContractRequest { ContractSpec contract = 1; }         // stock, index or option, fully specified, con_id zero
// FOUND: exactly one matching result. NOT_LISTED: an empty end or error 200. Several results, a differing result,
// a timeout or a connectivity error is a gRPC error (FAILED_PRECONDITION for several or differing, DEADLINE_EXCEEDED, UNAVAILABLE), never a cached negative.
message ResolveContractResponse { ResolveStatus status = 1; ContractSpec contract = 2; int32 error_code = 3; string error_text = 4; }
```

`marketdata.proto` (imports `contracts.proto` and `google/protobuf/timestamp.proto`):

```
// The market-data type is one setting of the gateway session, not of a request. Pyside sets it once after each
// connect from its configuration and reports it in PingResponse; a reconnect sets it again before any quote is served.
enum MarketDataType { MARKET_DATA_TYPE_UNSPECIFIED = 0; MARKET_DATA_TYPE_LIVE = 1; MARKET_DATA_TYPE_FROZEN = 2;
                      MARKET_DATA_TYPE_DELAYED = 3; MARKET_DATA_TYPE_DELAYED_FROZEN = 4; }
// Specification of each kind, held in pyside (spec.py) and written here so the caller knows what it gets:
//   OPTION_EOD: a short streaming subscription per option with generic ticks 100 and 101, released as soon as bid, ask,
//     close and the model values have arrived; at most 20 s; wanted fields bid, ask, close, volume, open_interest, model values.
//   UNDERLYING_IV: a short streaming subscription per stock or index with generic ticks 104 and 106, released when
//     option_implied_vol and historical_vol have arrived; at most 20 s.
// These first values are corrected from the owner's live measurement (ADR 0003: measure first), which is a change of
// comment and table, not of shape.
enum QuoteKind { QUOTE_KIND_UNSPECIFIED = 0; QUOTE_KIND_OPTION_EOD = 1; QUOTE_KIND_UNDERLYING_IV = 2; }
enum QuoteStatus { QUOTE_STATUS_UNSPECIFIED = 0; QUOTE_STATUS_OK = 1; QUOTE_STATUS_PARTIAL = 2; QUOTE_STATUS_NO_DATA = 3;
                   QUOTE_STATUS_NO_SUBSCRIPTION = 4; QUOTE_STATUS_TIMEOUT = 5; QUOTE_STATUS_ERROR = 6; QUOTE_STATUS_DISCONNECTED = 7; }

service MarketDataService { rpc Snapshot(SnapshotRequest) returns (stream SnapshotResponse); }
message SnapshotRequest { QuoteKind kind = 1; repeated ContractSpec contracts = 2; }   // every contract has con_id, else the call is INVALID_ARGUMENT
message SnapshotResponse { Quote quote = 1; }   // one message per requested contract, in completion order
message Quote {
  ContractSpec contract = 1;
  QuoteStatus status = 2;
  MarketDataType market_data_type = 3;          // the type the gateway reported for this quote
  int64 generation = 4;
  google.protobuf.Timestamp requested_at = 5;
  google.protobuf.Timestamp sent_at = 6;
  google.protobuf.Timestamp received_at = 7;
  optional double bid = 8; optional double ask = 9; optional double last = 10; optional double close = 11;
  optional double volume = 12; optional double open_interest = 13;
  optional double implied_vol = 14; optional double delta = 15; optional double gamma = 16;   // option model values
  optional double vega = 17; optional double theta = 18; optional double und_price = 19;
  optional double option_implied_vol = 20;      // generic tick 106 of an underlying
  optional double historical_vol = 21;          // generic tick 104 of an underlying
  int32 error_code = 22;                        // IBKR code, 0 when none
  string error_text = 23;                       // IBKR text after the log filter's scrub, only on error statuses
}
```

Semantics the Go side may rely on: one `Quote` per requested contract and no more; the stream ends after the last; a cancelled call or an expired deadline releases every line it held; at most 50 snapshots of the process are in flight
(the rest wait), so a large call is slow, not refused; a disconnect during a call gives every contract not yet answered `QUOTE_STATUS_DISCONNECTED` and ends the stream; `ResolveContract` obeys the comment above. No message holds an account identifier.
A batch resolve is not offered: adding one later is an added rpc and so `ibkr.v2` (`## Adversarial`, point 4).

Python entry of contracts, `pyside/src/optdesk/contracts/api.py` (declarations only): it re-exports the generated classes the pyside modules need from `optdesk.contracts.genpb.ibkr.v1` (messages, enums, the stubs, the servicer
base classes and the `add_*Servicer_to_server` functions) by plain `from ... import ... as ...` lines and `__all__`, no function bodies.

Generated Python: `contracts/generate-pyproto.sh` runs, through `uv run --project pyside --locked`, `python -m grpc_tools.protoc -I contracts/proto --python_out --pyi_out --grpc_python_out --mypy_grpc_out` into
`pyside/src/optdesk/contracts/genpb` (the last option is the typed-stub plugin of `mypy-protobuf`, found on the PATH that `uv run` sets), rewrites the generated imports `from ibkr.v1 import` to `from optdesk.contracts.genpb.ibkr.v1 import`
(POSIX tools or `uv run python` only, no `sed -i`), and writes empty `__init__.py` files. The output is committed with its source. Typed `*_pb2_grpc.pyi` stubs are why `mypy --strict` passes on callers of the stubs and servicer base classes
without an ignore comment or a relaxed flag.

Python seam private to module pyside (no other module imports it; listed so the issues agree). In `ibgateway.py` the objects of ib_async are named `ib` and `ib.client` and nothing else of ours is, which is what the greps rely on:

- `timing.py`: `Clock` protocol (`monotonic()`, `now()` timezone-aware UTC, async `sleep(seconds)`), `SystemClock` (the only place of `src/` calling `asyncio.sleep`), and `with_timeout(clock, awaitable, seconds)`, which races the awaitable
  against `Clock.sleep` (the only timeout mechanism of `src/`; `asyncio.wait_for` and `asyncio.timeout` are not used, so a fake clock governs every timeout). ib_async itself reads `loop.time()`, so tests never drive a real `IB`; they drive a fake `Gateway` or a fake `ib`.
- `pacing.py`: `MessagePacer` (sliding window, 40 starts per second, cancels included; a cancel is queued and sent by a drain task, so a cancel in a `finally` never waits and the rate still holds), `LineBudget` (leases, default 70, released in `finally`, `shrink(101)`; a second
  instance of 50 caps snapshots in flight), `DetailsLane` (the adaptive lane: start 2, at most 5, rises by 1 when a window of 10 answers started at the current limit has a mean under 1 s, halves to no less than 1 over 3 s, window emptied at each change; a request waits at most 20 s; a timeout drops the limit to 1 and pauses starts 30 s; no start while the oldest in flight is older than 5 s or while more than 2 timed-out requests are unresolved; the first answer after a timeout is no sample).
- `model.py`: frozen dataclasses `ChainRow`, `ResolveResult`, `QuoteRow` and the `Gateway` protocol (`open_session`, `status`, `chains`, `resolve`, `quotes`), all async, importing neither ib_async nor generated code.
- `spec.py`: the one table of request specifications per `QuoteKind` (the values written in the proto comment), the status rules and the error-code map. No strategy: no strike choice, no expiry window, no price arithmetic.
- `ibgateway.py`: the only file importing `ib_async`; `IbGateway(send_guard, ...)` implements `Gateway`; the constructor requires the guard installer, so there is no unguarded construction. It builds `ib = IB()`, installs the guard on `ib.client`, awaits `ib.client.connectAsync(...)`, sets the market-data type once, and
  hooks the client's disconnect (the worker takes the hook from `Client._onSocketDisconnected` / `apiEnd` of the pinned version) to fail the in-flight work with DISCONNECTED and bump the generation.
- `transport.py` (owner-only): the guard (`check`, `install_guard`, `OrderRefused`, `NotAllowed`), the log filter (`configure_logging`, field whitelist, `scrub`), the three servicers and `build_server`.
- `server.py`, `__main__.py`: configuration, the supervisor (reconnect with a backoff taken from the `Clock`), the socket, and the one `asyncio.run`.

Guard: ids 3, 4, 21, 58 raise `OrderRefused`; any id other than 1, 2, 9, 20, 25, 49, 59, 71, 78 raises `NotAllowed`. It is installed on `ib.client.send` and on `ib.client.sendMsg` before `connectAsync`. The handshake frame goes through `conn.sendMsg` and is safe because it is
the constant `API` prefix with the version range, sent before the API is started and carrying no request id; the test records the bytes and asserts that first frame is that prefix and that every later frame came through the guarded `sendMsg`.

Log filter: our code logs only through `log_event(logger, event, **fields)`; `event` is one of a fixed set of names and a field is allowed only if its name is in the whitelist (`rpc`, `kind`, `count`, `status`, `code`, `generation`, `elapsed_ms`, `limit`) and its value is a number, a boolean or one of a
fixed set of words. Any other record that reaches a handler (the library's, for example) is passed through `scrub`, which removes any token shaped like an account id (the shapes: letters then 5 to 9 digits, and the alias shape `acct_` plus 1 to 8 lowercase letters) and drops free text over 200 characters. `configure_logging` sets the logger `ib_async` to WARNING with its
own handlers removed and propagation on, so its DEBUG frames never reach a handler of ours.

Configuration, by environment variable, none holding a secret: `OT_HOME` (required; the socket is `$OT_HOME/run/ibkr.sock`, the directory is created mode 0700, the socket is chmod 0600, a stale socket file is removed, any other file at that path is an error), `OT_IBKR_GATEWAY_HOST` (default `127.0.0.1`),
`OT_IBKR_GATEWAY_PORT` (required), `OT_IBKR_CLIENT_ID` (nonzero, default 33), `OT_IBKR_LINES` (default 70), `OT_IBKR_SNAPSHOTS` (default 50), `OT_IBKR_MARKET_DATA_TYPE` (default 1, live). A missing required variable stops with a message that names the variable and no value. The process runs once per gateway; there is no
worker process or pool inside it (ADR 0003's "no separate worker process" is kept in that sense; the service itself is the plan's decision).

## Adversarial

The full answer of the adversarial review is `adv-pyside-ibkr-transport.md` in the dispatcher scratchpad (a local path, kept out of this public file). Its six points and what this revision did:

1. Gap against the goal: adopted. The 2026-10-16/17 amendments of ADR 0003 are carried in (the adaptive 1 to 5 lane replaces the one-at-a-time lane, the 50 snapshot cap, the 20 s wait and 30 s pause, the strike-union warning and the caller-side negative cache). The market-data type is session-global: it is set once per session, reported by `Ping`, and
   no longer a request field. Reconnect detection and the DISCONNECTED path are named. The Go client design gates the W3-4 jobs; the Brief and `## Left out` say so. The "no separate worker process" line is kept as no pool inside the process; the service itself is the plan's decision.
2. Biggest unnamed risk (safety paths): adopted. The guard covers `send` and `sendMsg`, the handshake frame is shown safe by a test, a refusal inside `reqMktData` returns the lease and cancels the ticker, cancels are queued so a `finally` cannot burst past the window, timeouts use the fake clock only. The statement that account ids are never stored is replaced by the truth:
   ib_async holds them in memory and logs the frames at DEBUG; our code never reads, logs, stores or sends them, the whitelist filter and the scrub enforce it on our handlers, and the `ib_async` logger is set above DEBUG, each with a test.
3. A simpler way: `Snapshot` without a conId is not adopted. Merging the pacing and gateway issues is not adopted (different tests,
   and the gateway issue is already large); the guard moved out of the gateway issue into the owner-only file, which makes it smaller. `types-grpcio` is kept for `grpc` itself, and a typed-stub generator (`mypy-protobuf`) is added for the generated stubs, which is the real mypy fix.
4. The reasons to accept and not to hold: the Go client cannot be designed against a shape nobody serves; the pacing makes a batch resolve unnecessary at this scale;
   the owner merges `contracts/proto/**` and `transport.py` and so has two points at which to hold the freeze; adding a field is backward compatible. The per-request `market_data_type` is removed before the freeze.
