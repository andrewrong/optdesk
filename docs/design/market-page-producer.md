Goal: `ot page --name market_page` and, after it, the route `/market` of `ot serve` (the unified site) give a `market_page` v1 built per request from stored data. The index table shows, for SPX, NDX and RUT, the 3-year percentile of VIX, VXN and RVX; the term block shows VIX and VIX3M today and five days ago; the weather block says how far the SPX is from its 200-day line. Every other field is a named Gap.

## What main holds today

- Schema and view exist: `page.market_page.v1.json` (blocks `weather`, `indices`, `term`, `breadth`, plus the envelope), `web/src/pages/market/MarketPage.tsx` registered as `market_page` with three fixtures (`ok`, `gap`, `stale`). No Go code writes the page and no route serves it (`missing-pages.md`: "The page has no route").
- The stored data that matches the page. `compute_figures` (`internal/jobs/computefigures/job.toml`) stores, as readings of kind `market` with the FRED id (the first series of its manifest entry) as subject: `market.vix_pctile_3y` (VIXCLS), `market.vxn_pctile_3y` (VXNCLS), `market.rvx_pctile_3y` (RVXCLS), `market.sp500_pctile_3y`, `market.sp500_vs_200d` (version 2, SP500) and `market.vix_term_ratio` (VIXCLS over VXVCLS). Each is `pages = []` in `register.toml` ("no page reads it yet"). The FRED series `VIXCLS`, `VXNCLS`, `RVXCLS`, `VXVCLS`, `SP500` are stored by `fredseries` and readable through `store.SeriesReader`.
- #553 is merged: `ot run-once` and `ot backfill` run `compute_figures` (`cmd/ot/runonce.go`), so the readings below are stored by a command the owner runs and by `ot scheduler`'s run of the day (the schedule is `docs/deploy/scheduler.md`). A reading has no field for its data day.
- No code of the page role can read a reading today (`ot_ro_pages` has `SELECT` on the view `rd.reading_r1` and nothing on the tables). Main holds the contract only: `store.ReadingViewReader` (`WinnerReadings`, a `compute.ReadingFunc` as a method value; one row per day, parameters filled) and `store.OpenReadingViewFunc` (`internal/store/api.go`, #591). The implementation `reading.OpenView` is the entry `report-reading-view-impl` of `docs/design/report-page-producer.md` (not merged); the wiring field `deps.openReadingView` is added by its entry `report-page-ot` (not merged). This design reads through them and adds no reader of its own.
- `docs/design/unified-site.md` (merged as a design, its code is the entry `site-ot-serve`, not merged) makes `ot serve [--day DAY] [--addr ADDR]` the one site: a route table in `cmd/ot/site.go` (`/home`, `/macro`, `/household`, `/positions`, `/risk`, `/options`, `/options/data`, `/advice` and `/assets/`), `siteHandler`, and `openSiteReaders`, which opens the stores once with `OT_PG_DSN_PAGES` (Decision 8 there). `/market` is not in its route table and not in its bar of eight; this design adds the route as its own entry after `site-ot-serve` and asks the owner about a bar item (Open questions).
- The Cboe indices are not at-the-money IV30 (glossary line 75), so the percentile is a different number from `market.ivp_own`. The percentile rule (`pctile_3y_v1`: 3 calendar years, strictly below, the day excluded, `short_history` until the stored history spans 3 years) is registered and hashed; nothing here changes it.

## Decisions

1. One new package, `internal/pages/market_page`, shaped like `report_page` of pull request 500 and `macro_page`: `Build(ctx, c Config, r store.SeriesReader, day, generatedAt) ([]byte, error)` and `NewPage(c Config) pages.Page` (`Meta{Name: "market_page", Schema: "page.market_page.v1"}`). The series reader is the argument of `pages.Builder` as for `macro_page`; the readings come from `Config.Readings`, a `compute.ReadingFunc`, so the package imports `contracts`, `store`, `compute` (the root) and `pages` only. `internal/pages/api.go` is not edited. There is no `api.go`: `Config` and `NewPage` are frozen by the first entry, `market-page-interface`, in `page.go` (see `## Interface`), so that the builder and the `ot` entries are written against it and not against each other; the figure ids and series ids are constants of the builder (`ids.go`). In `cmd/ot` only `wire.go` imports `market_page` and builds `Config` (Decision 8). Cells are built in this package, not in a second block package: the review of the shelved draft refused a package that nothing calls, and the cells ship with their caller. No new module row; the sentence of `modules.md` that lists the implementation packages `cmd/ot` imports gains `internal/pages/market_page` and `arch.toml` is regenerated, both in the merge of this design (`go run ./scripts/arch --check` prints `arch: ok`). `.go-arch-lint.yml` reads the tree, so it can be regenerated only once the directory exists: the interface entry does it with the first Go file, under the Licence below.
2. Per request, stored nowhere, no job and no schedule (owner 2b). Freshness reaches the page through `data_times`, `stale` and the Gaps. Run status is `ok` when every field this page has a source for is filled (the weather headline and sentence, the `rank_3y` of SPX, NDX and RUT, and the four term cells; the term sentence is a fixed text when `market.vix_term_ratio` has no reading and is not a Gap, so its absence alone leaves the page `ok`), and `partial` when any of them is a Gap; the permanent Gaps (`not_built` blocks and cells, the N225 rank) do not make a page `partial`, they are listed in `gaps`. It is never `failed`: a reader error is an error of the call (`ot` answers 500 with a fixed text), never a Gap.
3. Where each field comes from (the list the producer must fill):

   | field | source | state |
   |---|---|---|
   | envelope: `schema`, `schema_version` 1, `run_id`, `build_id`, `scope`, `generated_at` (the owner's zone, `Config.Zone`, as `macro_page`), `run_status`, `title`, `sentence`, `notes` | constants of `strings.go` and `Config`; `run_status` by Decision 2 | filled |
   | envelope `gaps` | the Gap objects of the blocks, copied in page order after the blocks are built (so it never disagrees with them, as `CardNotes` shows both) | filled |
   | `data_times` | one `SourceTime` per series id (`VIXCLS`, `VXNCLS`, `RVXCLS`, `VXVCLS`, `SP500`), the source being the series, never a figure; its time is the newest data day among everything that reads the series, a reading's `data_day` (Decision 5) or a term point's date (Decision 6), midnight in the zone; a series none of whose readings or points has a data day has no entry | filled |
   | `stale`, `stale_after` | the oldest data day of the page, `is_stale` when it is more than 4 calendar days before the request day (the display limit of `macro_page`; the register's `max_age_days` of these figures is 8 and decides the `stale_input` Gap, so a figure `ok` at 5 to 8 days old shows its value and the page label says `数据日 MM-DD`: two rules for two things, not a copy), text `数据日 MM-DD` | filled |
   | `weather.headline`, `weather.sentence` | reading `market.sp500_vs_200d` (SP500): `headline` is a fixed text with no number; `sentence` carries the signed percent (`与 200 日线相差 +3.12%`, Decision 4) | filled; Gap text when no reading |
   | `weather.chart` | needs a stored 200-day line per day: none (`market.spx_close` is registered, not computed) | Gap `not_built` |
   | `indices.rows[]` SPX, NDX, RUT: `rank_3y` | readings `market.vix_pctile_3y` (VIXCLS), `market.vxn_pctile_3y` (VXNCLS), `market.rvx_pctile_3y` (RVXCLS) | filled; Gap by the reading's state |
   | `indices.rows[]` N225: `rank_3y` | no FRED series for the Nikkei volatility | Gap `no_data` |
   | `indices.rows[]` all four: `iv` | `market.index_iv` is the IBKR live value, no stored reading | Gap `not_built` |
   | `indices.rows[]` all four: `rv20`, `iv_minus_rv20` | no figure of a 20-day realised volatility of an index exists | Gap `not_built` |
   | `indices.title`, `sentence`, `columns`, `note` | constants | filled |
   | `term.points[]` `1M` (VIXCLS) and `3M` (VXVCLS): `today`, `five_days_ago` | the stored series points (Decision 6) | filled; Gap per cell |
   | `term.sentence` | reading `market.vix_term_ratio` (VIXCLS) | filled; fixed text when no reading |
   | `breadth` | no figure of the share of stocks above a moving average, and no constituent data | Gap `not_built` |

   Nothing in this table is computed by the page. Every number is a stored reading or a stored point; the page shifts a decimal text, rounds it and writes it (Decision 4), and picks a stored point by its date (Decision 6).
4. Number text and unit, by string arithmetic. A stored reading is decimal text (`0.685000`). The percentile cell is a share: unit `share_percent` of `common.v2.json` (`SharePercentFigure`: whole percent, 0 to 100, `ROUND_HALF_EVEN`), so stored `0.685000` is value `68`, text `68%`. The review of the shelved draft found `percent` wrong for a percentile: in `common.v2.json` `percent` is a signed change (`+2.1%`). The market schema does not bind the choice (`Figure.unit` there is a free lowercase word and the view reads `text` and `value` only), so `share_percent` is a designer's choice made for honesty of the name and for the day the web reads `unit`, not a schema rule. The weather figure is the signed change: stored ratio `0.031250` is unit `percent`, text `+3.12%` (two decimals, half-even). The term ratio is unit `ratio`, text with two decimals (`0.90`); a series point is unit `index_points`, text with two decimals. One helper, `shiftRound(text string, shift, decimals int) (string, error)`, uses `math/big` (exact decimal, no float): it shifts the text by `shift` places and rounds half-even to `decimals` places. The JSON number of a `Figure.value` is written as `json.Number` of that same text, so no `float64` appears in the package except where a series point is formatted (`strconv.FormatFloat(v, 'f', 2, 64)`, in `format.go` only). A text that is not a decimal, or a percentile outside 0 to 1, is a `missing_input` Gap (`bad_input` of the reading), never a number.
5. Readings and the data day. The package asks `Readings` for each figure over the 6 days `day-5` to `day` and takes the newest day returned (the window of 492 `Evaluate`). The row is one of four cases, by `state` and the numeric `reason_code`:
   - `ok` with a value: the figure.
   - `missing_input`, code 2 (`short_history`): Gap `no_data`, text `历史不满 3 年，不给分位` (the glossary words).
   - `missing_input`, code 3 (`stale_input`): Gap `stale_input`, text `分位数据已过期，数据日 MM-DD` (the day is the `data_day` below; without one, `分位数据已过期`).
   - `missing_input`, any other code (1, 4, 5) or an `ok` row without a value: Gap `missing_input`, text `分位暂缺：输入不全`.
   - no row: Gap `no_data`, text `分位暂无数据：还没有存储`.
   The data day of a reading is the value of its parameter `data_day` (a `value_tag` of the form `YYYY-MM-DD`), never its `day` (the as-of day of the run, which can be later than the newest input). A reading with no such parameter or a bad one has no data day: the figure is still shown, it adds nothing to the `data_times` entry of its series and does not enter `stale`; the series keeps an entry only if another reading or a term point of the same series has a data day (so `VIXCLS` is left out of `data_times` only when its percentile reading has no `data_day` and the term block has no `VIXCLS` point). The shelved draft read "the day of the newest point" from a field that does not exist; this is the one it can use. The wording of the Gaps is constants of `strings.go`.
6. Term block. `1M` is `VIXCLS` and `3M` is `VXVCLS`, stored series (`seriesUnits` `index_points`). For each, the builder reads `SeriesPoints` for the 40 days before the request day, keeps one value per observation date (the greatest `RealtimeStart` not after the day, as `macro_page`'s `latestPoint`), and picks: `today` is the newest stored point on or before the day, if it is at most 4 days old, else Gap `stale`; `five_days_ago` is the newest stored point on or before the date 5 calendar days before the `today` point, if it is at most 4 days older than that date, else Gap `no_data`. A series with no point at all gives both cells a Gap `no_data`. If all four cells are Gaps the whole `term` is one Gap `no_data`. Picking a stored point by a date is selection, as `macro_page` does; nothing is summed or compared.
7. How the pages reader is opened. The reader is `reading.OpenView(ctx, dsn)` of `report-reading-view-impl`, reached only through `deps.openReadingView` (`store.OpenReadingViewFunc`; the field is added by `report-page-ot`, this design adds no second field), with the DSN of the `.env` line `OT_PG_DSN_PAGES` (`store.DSNEnvPages`; a missing line is an error that names the variable and no value). `ot page`: `marketPage` in `cmd/ot/market.go` opens it once per command, with the series store of `seriesReader`, and closes both on return. The site: `openSiteReaders` (`cmd/ot/site.go`) gains one field `readings store.ReadingViewReader` opened with the same DSN once per process and closed with the other stores (a failed open closes those already opened). `Config.Readings` is its method value `WinnerReadings`. The page imports no opener. No new `.env` line, no grant, no migration. The two `ot` entries therefore depend on `report-reading-view-impl` and `report-page-ot`: the first merged shapes `openReadingView`, the other rebases; this design never defines that field itself.
8. Serving, two entries. `cmd/ot` reaches the builder through one field of `deps`, `marketPage`, whose type takes plain arguments, `func(zone *time.Location, runID, buildID, scope string, readings compute.ReadingFunc) pages.Page`; its real value in `wire.go` builds `market_page.Config` from them and calls `market_page.NewPage`, as `newMacroPage` does for `macro_page`. So `market.go` and `market_site.go` fill the arguments and never name `Config` or import `market_page`; only `wire.go` imports it. `ot page --name market_page` (`market-page-ot-cmd`) prints the page; the route `/market` of the unified site (`market-page-site-route`, after `site-ot-serve`) serves it, built per request, GET and HEAD. The bar of eight items is not changed here: `/market` is reached by its address, which differs from `unified-site.md` Decision 3 and 4 ("no page hidden"); that is a named exception, with an owner question (Open questions), not an accident. The demo profile opens no store: a demo reading function returns fixed synthetic readings with the parameter `data_day`.
9. History is the owner's act, owned by a runbook item. The percentiles show a value only when the stored FRED history of the three index series spans 3 years before the day. That history is loaded by the owner with `ot series-load --series VIXCLS --series VXNCLS --series RVXCLS --from DAY --to DAY` (exists on main; the loader refuses a range over 5 years, so one run covers 3 years and a margin; `--from` is at least 3 years and 10 days before the first day a percentile is wanted, because the first stored point must be on or before day minus 3 years and that date may be a weekend); the readings are stored by the next `compute_figures` run (it computes the as-of day only; the owner can run `ot run-once` for the day to get them at once, which the window may do under `owner-allows-ot-commands`). Until then the page says `历史不满 3 年，不给分位`, which is true. The runbook is a file of the docs entry of this design; the owner's run of `ot series-load` is not an agent step (the window runs it only with the owner's word) and no test sees it, so readiness is a runbook item with the page's own words as the check: until it is done the page says `历史不满 3 年，不给分位`, which is true. The history asked of the owner is the three Cboe series; the IBKR live index value is not part of this and comes only after a CBOE market-data subscription probe (owner decision).
10. The register. The `pages` line of a figure names a page that reads it; it is set only by the issue that makes a page read it. The docs entry therefore comes last: it is cut after `market-page-site-route` and `market-page-builder` have merged, and sets `pages` of the five figures this page reads (`market.vix_pctile_3y`, `market.vxn_pctile_3y`, `market.rvx_pctile_3y`, `market.vix_term_ratio`, and `market.sp500_vs_200d` version 2) to the page paths, with one `history` line each and no change of `version`, `formula` or `source_hash` (a changed formula would be a new version and a new hash; this is not one). `market.sp500_pctile_3y` stays `pages = []` (no row reads it). It lands after `/market` is served, so the register never names a reader that is not served.
11. Libraries. None new: `encoding/json`, `math/big` and `santhosh-tekuri/jsonschema/v6` (already in `go.mod`; it validates the output against the schema in the tests). Own code only where no library fits (a decimal shift and half-even rounding of a decimal text: `math/big` gives exact arithmetic, and no mainstream library does this one step more simply). The shift-and-round helper is own glue in one file (`shift.go`) so a library can replace it.

## Interface

Owner: pages, `internal/pages/market_page/page.go`, declarations and one stub body (the entry `market-page-interface`). The stub is allowed here, as in `report_page`, because the interface entry must compile and its contract test calls `Build` from both sides before the builder exists; it is one function body with no logic beyond returning the fixed error, and the builder entry changes that body and no declaration (its acceptance checks the diff). The contract between `ot` and the builder is `Config` and `NewPage`, of the same shape as `macro_page`; the stub `NewPage` returns a `pages.Page` with the Meta below whose `Build` answers a fixed error `market_page: not built`; the builder entry replaces that one body and changes no declaration:

```go
type Config struct {
	RunID, BuildID, Scope string
	Zone                  *time.Location // generated_at is written in it; nil is an error of Build
	Readings              compute.ReadingFunc // the method value WinnerReadings of the page-role reader; nil is an error of Build
}
func NewPage(c Config) pages.Page // Meta{Name: "market_page", Schema: "page.market_page.v1"}
```

The figure ids and series ids are constants of `ids.go` (builder entry); a test reads `internal/compute/rules/rules.json` and `internal/jobs/computefigures/job.toml` and fails if one names an id that does not hold, so a later figure rename fails a test and is not an interface change. Schema: unchanged (`Contracts: unchanged`).
