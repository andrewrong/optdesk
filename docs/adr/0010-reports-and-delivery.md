# ADR 0010: Reports, phone access and Telegram

Date: 2026-10-02
Status: accepted

## Context

The owner reads reports on the Mac and on the phone, and wants a Telegram message when one is ready. Reports contain account data, which must not be stored or processed by any third party. ADR 0005 said no notifications; the owner has since asked for Telegram.

Two advisor models debated this over three rounds; the record is kept outside the repo.

## Decision

**Report files**
- Each run writes an immutable HTML file `reports/<date>/<run>.html`, atomically, and validates it before publishing. A failed run leaves the previous report in place.
- Pages show generation time, account-data and market-data "as of" times in KL time, and run status. A page older than its expected window shows "STALE — do not act"; a page with a newer report shows a link to it.
- Mobile layout: single column, readable text, wide tables scroll inside their container. Freshness and capital checks first.
- Reports carrying FX place Reference data immediately after FX and before valuation, with freshness, dated last valid values and a replay sequence (ADR 0015).
- No JavaScript (except the two files of the amendment of 2026-10-18), web fonts or remote assets. All text is HTML-escaped.
- Files live outside Git and cloud-synced folders. History is kept for 90 days.

**Phone access**
- `serve` (ADR 0005) runs a read-only report listener on 127.0.0.1 only, separate from the control API. It starts and stops with `serve`, so after a reboot it comes back when the owner starts the service.
- Tailscale Serve publishes it on the tailnet over HTTPS. Funnel is never used.
- Every request must carry the owner's exact `Tailscale-User-Login`; otherwise 403. Tagged devices such as the VPS get no identity header and are refused.
- The tailnet policy grants only the owner's devices access to the report port, with policy tests that deny tagged devices.
- Headers: `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, and a CSP with `default-src 'none'`.
- The owner does the Tailscale setup by hand: HTTPS, policy, `tailscale serve`. A neutral machine name is chosen before the first certificate, because certificate names are public.

**Telegram**
- Telegram never carries account-derived information (owner decision): no holdings, balances, percentages, sizes, or tickers chosen from holdings.
- Messages: "report ready" with the immutable report link, a failure notice, and market-only summaries (freshness, market candidates from the watchlist, exclusions).
- An in-house renderer: HTML parse mode, escaping `& < >`, splitting at block boundaries below 4096 characters. A block still too large becomes an HTML attachment of market-only content. Plain text if a send fails.
- Link previews are disabled. The bot token lives outside Git and is never logged.

## Consequences

- ADR 0005's "no notifications" is superseded for Telegram.
- Work order: report generator → report listener → Telegram.

## Amendment (2026-10-03)

Tailscale Serve is replaced by a direct bind to the discovered Tailscale IPv4 only.
The owner login is discovered from local CLI status; peer identity comes from
`tailscale whois` on the connection's IP, never an HTTP identity header.
Plain HTTP is accepted because WireGuard encrypts tailnet traffic.
Funnel and public exposure remain forbidden. No manual Tailscale configuration is required.
Any local user on the Mac, and devices behind an owner-owned subnet router, resolve to the owner.

Report-ready notices and fixed generic attention alerts use separate optional Telegram

2026-10-19: the report listener answers only requests whose `Host` is the bind address, the machine's MagicDNS full or short name at the listener's port, or the host and port of the configured `OPTION_TRADER_REPORT_BASE_URL`. It checks every request, GET and HEAD alike, after the owner check and before routing: a missing or repeated `Host` gets 400, any other value 421 (Misdirected Request), and the log line never holds the value. The reason is DNS rebinding: a page on another site can point a name of its own at the Tailscale address, and the owner's browser would then fetch and let that site read the report pages as the owner, which the owner check cannot stop because the request comes from the owner's own device. Routes, methods and responses are otherwise unchanged.

2026-10-19: GET/HEAD on all routes; POST only on the plan edit paths that exist (/plan/price-lines since this change); Host allowlist on every request.

## Amendment (2026-11-08)

2026-11-08 (owner decision, optdesk-1074; `docs/design/risk-alerts.md` Decision 10, choice (a)): for market alerts only, the Telegram text may hold the rule title, the public market figure and its value, and the day of its data. It never holds anything derived from holdings or the account: no positions, balances, percentages, sizes, or tickers chosen from holdings.

The account-derived ban ("Telegram never carries account-derived information", under **Telegram**) stands for what it covers. The job alert rule (a registered job id, status and the owner's local time) stands for job alerts; this amendment does not widen it.
