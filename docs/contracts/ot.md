# ot contract

## Responsibility

`ot` is the optdesk binary, the composition root (`cmd/ot`). It selects the profile and the log handler through `internal/profile`, and dispatches to 10 subcommands: `backfill`, `calendar`, `migrate`, `page`, `run-once`, `scheduler`, `serve`, `series-load`, `setup` and `version`. A subcommand registers itself in an `init()`; a name registered twice panics. Without a command, or with a name that is not registered, `ot` prints `usage: ot <command> [args]` and the sorted list of commands on standard error.

The subcommands:

- `ot run-once [--dry-run [--job NAME]...] [--day DAY]`: opens the stores and the broker, wires the six jobs `fred_series`, `option_eod`, `quote_snapshot`, `compute_figures`, `calendar_refresh` and `earnings_refresh` and reconciles the day (`Reconcile`) with them, in one call; `ot` passes the zero `runner.WindowRule{}` and each job states its window through `runner.Windowed`. `earnings_refresh` is left out, with one log line naming the missing line (`ALPHA_VANTAGE_API_KEY is not set` or `OT_PG_DSN_EVENTS is not set`), when either line is empty; the other five run. `option_eod_jp` (the Nikkei 225 index options of `OSE.JPN`, after `option_eod`) is wired only while the `XTKS` calendar answers for today; otherwise it is left out, with one log line `calendar XTKS is not loaded` (no path), and the other jobs run as before. It makes no second call to a vendor on the same day: the job reads the rows of the day and writes none for an entry that has one (Decision 12 of `docs/design/event-sources.md`). Real profile only. After `Reconcile` returns it reads the day back from the ledger (`Present` and `Runs`) and prints to standard output one line per expected key and job: `job=<job> day=<day> dataset=<dataset> subject=<subject> outcome=<captured|no_value|empty|failed|missing>`, with `rows=<UsableN>` for `captured`, `reason=<ReasonCode>` for `empty` (`empty_before_close` is printed `before_close`), `reason=<ErrorCode>` for `failed` and `reason=no_value` for `no_value`. A job left out (`earnings_refresh` with its line missing) prints `job=<job> day=<day> outcome=left_out reason=<ALPHA_VANTAGE_API_KEY is not set or OT_PG_DSN_EVENTS is not set>`. The last line is `run-once <day> status=<ok|nothing_captured> captured=<N> keys=<M>`: `nothing_captured` when no key is `captured`, else `ok`. The exit code is 0 for both statuses (a day with no capture is not a failure of the command); the log line `run-once <day> done status=ok` is gone. A day at or before the day of the ledger cursor is an error (exit 1) that names both days and logs no `status=ok`: `Reconcile` walks only days after the cursor, so there is nothing to reconcile; the error adds the hint `use ot backfill --day <day>`.
- `ot run-once --dry-run [--job NAME]... [--day DAY]`: a smoke test of the broker jobs against the live broker socket `$OT_HOME/run/ibkr.sock` at any time of day. `--job` repeats and names `option_eod`, `option_eod_jp` or `quote_snapshot` (default: all three; any other name, such as `fred_series`, or `--job` without `--dry-run` is a flag error that names the three). It takes no instance fence, opens no store and no ledger, reads no DSN (the socket path comes from `OT_HOME`; `.env` is not read), and does not call the runner: no window, no skip of a present key. It builds each job through `newOptionEod`, `newOptionEodJP` and `newQuoteSnapshot` over an in-memory instrument resolver (ids from a counter) and in-memory writers that keep the rows, with a fixed clock on `--day` that no guard refuses: 16:30 in `America/New_York` for `option_eod`, 16:00 in `Asia/Tokyo` for `option_eod_jp` (after `freeze_after`, before its `stop_after`), and the slot of the key read as local time in the manifest zone of `quote_snapshot`, inside its window whatever its grace (zero included): the zone is not exported by the job, so for each key the dry run tries the slot at every UTC offset of a quarter hour from -12:00 up and keeps the first run that is neither a `no_value` nor an empty answer, or the `no_value` just before an empty answer (a `no_value` from inside the window, such as no quote, is reported as `error=no_value`). It calls `Plan` once per job and `Run` once per planned key, so an error belongs to one key. Nothing is written to PostgreSQL, the ledger or the cursor. Output on standard output, one line per job and key: `dry-run job=<job> day=<day> dataset=<dataset> subject=<subject> requested=<N> ok=<N> partial=<N> no_data=<N> elapsed=<duration> error=<code or none>`, where `requested` is `JobResult.Returned`, `ok`, `no_data` and `partial` count the rows the sink took with status 1, 2 and any other status (3, 4, 5), and `error` is the kind of the `TypedError` of that key (`none` when nil; a failed `Plan` prints one line with dataset and subject `-`). The last line is `dry-run <day> status=<ok|failed> keys=<M> failed=<F>`: `failed` counts keys with an error and the status is `failed` when F is above 0. The exit code is 0 for both statuses (a smoke test reports; it does not gate) and 1 for a flag error or a missing or too long socket path; when the broker dial fails the command returns the dial error (exit 1) and prints no summary line.
- `ot backfill --day DAY [--dataset ID]`: opens the stores and the broker, wires the same six jobs (`earnings_refresh` left out as for `run-once`) and calls `Backfill` for DAY: it re-runs the keys of that day that are missing or marked `no_value`, and moves neither the cursor, a plan nor a window. `--day` is required. Real profile only (the demo profile is refused with `backfill needs a real profile; the demo profile opens no store`). A day ahead of the cursor is refused with `day <day> is ahead of the cursor <cursor>: use run-once` (the cursor is `(none)` when empty); a day with no stored plan is refused. The error text of the runner is withheld because it may hold a DSN or a key.
- `ot scheduler`: the resident process that owns the instance fence and runs the ticker (`sched.New`). It takes the advisory lock first (`InstanceFence.TryLock`), retrying every 5 seconds for 60 seconds of the injected clock, and exits non-zero (not 75) when it stays held. It then opens the stores as `run-once` does and wires the same six jobs (`compute_figures` and `calendar_refresh` are never left out), records the build with `SetState`, hands the held fence to the ticker, serves `GET /health` on the loopback address `127.0.0.1` at the port of `OT_SCHED_HEALTH_PORT` (default 8765; 200 while the fence is held and the last tick is under 60 seconds old, else 503; other paths 404, other methods 405) and runs until interrupt or SIGTERM, then drains. Real profile only. The scheduler process then holds the runner, readings, loader and alerts DSNs (`OT_PG_DSN_ALERTS` is required, for the sent store of the alert pass; `OT_PG_DSN_READINGS` and `OT_PG_DSN_PAGES` are required for `compute_figures`; `OT_PG_DSN_LOADER` for `calendar_refresh`, whose store is the only one opened with it). An empty `FRED_API_KEY` is allowed and leaves `fred_series` out; an empty `ALPHA_VANTAGE_API_KEY` or `OT_PG_DSN_EVENTS` is allowed and leaves `earnings_refresh` out, alone, with the reason `ALPHA_VANTAGE_API_KEY is not set` or `OT_PG_DSN_EVENTS is not set` (both lines are read once at start, so the job comes back only after a restart; the scheduler runs it once per `XNYS` session day, after the close); a failed broker dial leaves `option_eod`, `option_eod_jp` and `quote_snapshot` out. The probe of `option_eod_jp` checks the `XTKS` session for today before the broker and returns `calendar XTKS is not loaded` while it fails; each rebuild of the reconciler re-probes an enabled `option_eod_jp` and builds without it when that is the reason, so a reconciler rebuilt after XTKS ran out never holds the job (the owner loads the calendar and restarts). Each left-out job is logged once (job id and reason, no key and no path) and comes back on the first tick whose probe passes, with no restart (`fred_series` with an empty key does not: it needs a restart with the key). A missing DSN is an error. `ot run-once` and `ot backfill` try the same lock first and refuse, with a text naming `ot scheduler status`, while it is held.
- `ot scheduler status`: reads `ops.*` through `store.SchedulerLedger` (the runner DSN only) and prints the build recorded by the running scheduler, the non-terminal runs with day and the age of the last heartbeat, the next slot of each job (with the reason of a left-out job) and the open gaps (the dataset for a key gap, the job for a preflight gap). Exit 0 when no gap is open and no job is left out; exit 1 otherwise, with the reasons in the error line. It opens no dataset store and no broker. Real profile only.
- `ot scheduler can-restart`: exit 0 and `ok` when a hand restart is safe; exit 1 with the reason when a run is not finished, or a job marked `restart_sensitive` is between its slot start and its window close (read from `ops.scheduler_job`). Same stores as `status`: none but the ledger. Any other first argument of `ot scheduler` is a usage error.
- `ot notify --once [--dry-run] [--quiet]`: one pass of the missed-job notifier, for the owner to test the Telegram token. It reads the open gaps through `store.SchedulerLedger` (runner DSN), sends at most one text and marks the gaps printed in it. It takes no scheduler lock and starts no site. `--dry-run` prints the text to stdout, needs neither `OT_TELEGRAM_TOKEN` nor `OT_TELEGRAM_CHAT_ID`, and marks no gap. Without `--quiet` the quiet hours are off, so a test works at any hour; `--quiet` keeps the default 23:00 to 07:00 in the owner's zone. A missing Telegram line is an error that names the variable and nothing else; no flag, log line or error holds the token, the chat id or a DSN. `ot notify --once` then makes one morning pass (`NotifyMorning`): inside the window 08:00 to 12:00 of the owner's zone, and when today's mark is not in `alerts.sent`, it sends the morning text; it needs `OT_PG_DSN_ALERTS` (the sent store) and reads the gap history and the expectations with `OT_PG_DSN_PAGES`. With `--dry-run` the morning text goes to stdout through the dry-run sender and no day mark is written; the quiet-hours flag decides the gap and alert quiet window only. `ot scheduler` reads the same two lines at start (a missing line is an error that names the variable, before the lock is tried) and calls the notifier after each gap pass, then the alert pass, then `NotifyMorning` (one sent store is opened for both); a failed or panicking notify pass is logged by class and never stops the ticker. Real profile only.
- `ot alerts check [--file PATH]`: loads an alert rule file, prints `rules: N` and then each rule id, one per line, and opens no database. Without `--file` it checks what `ot scheduler` loads: `$OT_HOME/alerts.toml` when the file exists, else the rules embedded in the program; a named file that is absent is an error. A bad file is an error that names the key and the rule id and no value. Flags, output and errors hold no token, chat id or DSN. The scheduler also runs the market alert pass after the gap pass of each tick, in the same quiet hours and with the same Telegram sender as the gap notifier: it reads `OT_PG_DSN_ALERTS` (required, a missing line is an error that names it before the lock is tried), loads `$OT_HOME/alerts.toml` when it exists (a bad file stops the start) else the embedded rules, opens the sent store with that line and the winner reader `WinnerReadings` (the reading view of `OT_PG_DSN_READINGS`, the rows the report page reads, not the newest-rev reader), and logs a failed or panicking alert pass by class without stopping the ticker. No resident process or health change is added.
- `ot page [--day DAY] [--out FILE] [--name NAME] [--market us|jp --slot open|close]`: builds the macro rates page once and writes its bytes. With `--name report_page` it builds the report page: `--market` (`us` or `jp`) and `--slot` (`open` or `close`) are both required for this name, and a missing or invalid one is an error that names the flag and opens no store. The report is built from stored readings through one `ReadingViewReader` opened once with `OT_PG_DSN_PAGES` (role `ot_ro_pages`, no other DSN line) and closed on exit; its `risks` block is `risks_block.Build` over `alertrules` and `WinnerReadings`, and the other four blocks are gaps of reason `not_built`.
- `ot serve [--day DAY] [--addr ADDR]`: serves the whole site over HTTP until interrupted, from one process, on eight stores opened once at start with `OT_PG_DSN_PAGES` (the series store, the five option stores, the reading-view reader of the report and the candidate store; closed on exit) or, with the demo profile, on in-process demo readers (seven series, two underlyings) that open no store. Run the web build first: `pnpm --dir web build` writes the bundle into `internal/pages/embed/dist`, which `ot serve` embeds. `serve` has no `--site` and no `--name`; either is an unknown-flag error and binds no port. Three kinds of route (under the root of the site): live `/macro` (the macro rates page, built per request from the series reader for the day of `--day` or else today) and `/options/data[/<id>]`; the live route `/report?market=us|jp&slot=open|close` (the report page, built per request from the reading-view reader for the day of `--day` or else today; a missing or invalid `market` or `slot` answers 400 with the fixed text `bad request`; `report_page` is reached only by this route, `ot serve` has no `--name`); the six sample routes `/home`, `/household`, `/positions`, `/risk`, `/options` and `/advice`, which read no store and answer the view model `{"schema":"sample_page","schema_version":1,"page":"<schema>"}` (`home_page`, `household_page`, `positions_page`, `household_risk`, `option_page`, `advice_page`); and `/assets/*`, the bundle files. `/` answers 302 to `/home`; any other path is 404 and a method other than GET and HEAD is 405. A build or catalog error answers 500 with the fixed text `internal error` and logs `component=ot status=failed` only. `/options/data` serves the underlying with the greatest latest `session_day` of the catalog (lowest id on a tie; id 0 and the empty page when the catalog is empty); `/options/data/<id>` serves a positive integer id. The option page is built per request; the catalog is asked with `since` 7 days before the build day, its entries are the page's choices (the instrument name, else `Underlying <id>`; `/options/data/<id>`); the names of the chosen id and of at most 50 catalog ids come from one read per request, and an id with no name or of type `option` keeps `Underlying <id>`. With an empty catalog the page carries the note `No option data is stored yet; collection has not run.`, the underlying label `No underlying yet` and no name read; a non-empty catalog adds no note. A failed open of any of the eight stores closes those already opened.
- `ot series-load --series ID [--series ID ...] --from DAY --to DAY`: loads the history of FRED series once, through `deps.newSeriesHistory` (`jobs.SeriesHistoryLoader`); `ot` only wires it: it builds the FRED source and the series writer and calls `Load` once. `--series` is repeatable and all three flags are required, with no default; a day that is not `YYYY-MM-DD` is an error. Real profile only (the demo profile is refused with `series-load needs a real profile; the demo profile opens no store`). It prints one line `<series> fetched <n>` per series, the count of points fetched, and no value. The range rules are the loader's. A loader error is shown by its class only (`retryable`, `permanent`, ...), because its text may hold a key. The owner runs it with the window the owner chooses; no CI step runs it.
- `ot setup pg`: sets up the PostgreSQL roles through `store.SetupFunc`, under the administrative DSN.
- `ot probe dividends [--symbols SYM,SYM,...]`: asks IBKR through `deps.newReference` (`broker.NewReferenceFunc`, `grpcbroker.DialReference`, the socket `$OT_HOME/run/ibkr.sock`) for the next ex-dividend date of a fixed list (US: AAPL, MSFT, KO payers, TSLA non-payer, SPY ETF; JP: 7203, 8306 payers), one call per market, and prints one line per symbol (`<market> <symbol> ok|no_value|timeout|error|ok_no_date [YYYYMMDD]`) and then `probe: US pass|fail`, `probe: JP pass|fail` for the markets of the run. A market passes when every payer is `ok` with a parsable `YYYYMMDD` date and no non-payer or ETF is `error` (`no_value` and `timeout` are fine there). `--symbols` limits the run to the named symbols of the list (an unknown one is an error) and so to their markets. Exit 0 only when every market of the run passes, else 1. It opens no store and reads no DSN or key; the output holds no key, DSN, path or account text. The owner runs it on the gateway machine and commits the output as `docs/design/event-sources-probe.txt` (Decision 6 of `docs/design/event-sources.md`).
- `ot version`: prints the version and the profile.
- `ot migrate [--dir DIR]`: applies the migration files of a directory under the administrative DSN, as the owner role.
- `ot calendar load FILE [FILE ...]`: reads session-day calendar files and upserts their rows through the session-day store, with the DSN of `ot_loader` from `OT_PG_DSN_LOADER`.

## Inputs

Flags (each command parses its own; an unknown flag or a bad flag value is a flag parse error):

| Flag | Commands | Default |
|---|---|---|
| `--day` | backfill (required, no default), page, run-once (also with `--dry-run`), serve | today in the market zone `America/New_York`, formatted `YYYY-MM-DD`; a value that is not `YYYY-MM-DD` is an error |
| `--dry-run` | run-once | off; on: the live-broker smoke test of `option_eod`, `option_eod_jp` and `quote_snapshot` into memory, exit 0 for both statuses |
| `--job` | run-once (with `--dry-run` only), repeatable | all three broker jobs; else `option_eod`, `option_eod_jp` or `quote_snapshot` |
| `--dataset` | backfill | empty: every key of the day; else one dataset id |
| `--name` | page | `macro_rates`; also `macro_page` and `report_page` |
| `--market`, `--slot` | page (`report_page` only; both required for it) | none; `us` or `jp`, `open` or `close` |
| `--out` | page | empty: the page goes to standard output; else it is written to that file |
| `--addr` | serve | `127.0.0.1:8080` (the loopback host on port :8080) |
| `--dir` | migrate | `migrations` |
| `--series` | series-load (required, repeatable) | none |
| `--from`, `--to` | series-load (required) | none; a day `YYYY-MM-DD` |

`ot migrate` takes no argument besides `--dir`. `ot setup` takes exactly one argument, `pg`. `ot calendar load FILE [FILE ...]` needs `load` and at least one file; any other form prints the usage line `usage: ot calendar load FILE [FILE ...]` as the error.

The two lines of `earnings_refresh` are not required. All nine lines read by `ot run-once` and `ot backfill` (the three above, `OT_PG_DSN_RUNNER`, `OT_PG_DSN_SERIES_FRED`, `OT_PG_DSN_PAGES`, `OT_PG_DSN_READINGS`, `OT_PG_DSN_LOADER` and `FRED_API_KEY`; `OT_CALENDAR_UV` is optional) are required; a missing one is an error that names the line.

The broker socket is `$OT_HOME/run/ibkr.sock`, created by the pyside service; `ot` only connects to it and creates, writes and chmods nothing there. A path of 104 bytes or more is refused before any store is opened with the error `socket path too long` (the text holds no path). The dial is made once, before `Reconcile`; when it fails, `ot` logs the failure once (step name only) and the two option jobs get a stand-in broker whose every call answers a retryable error `broker is not reachable`, so the option keys end retryable while `fred_series` still runs. The runs inside a day are several calls of `ot run-once` a day by `ot scheduler`; the cursor holds while a slot key is open.

The `OT_PG_` names are the constants `store.AdminDSNEnv`, `store.DSNEnvRunner`, `store.DSNEnvSeriesFred` and `store.DSNEnvPages`, `store.DSNEnvLoader`, `store.DSNEnvOptionEod`, `store.DSNEnvQuoteSnapshot`, `store.DSNEnvMaster`, `store.DSNEnvReadings` and `store.DSNEnvAlerts` of `internal/store/api.go`. A name that is unset or empty is an error that names the variable and no value (`OT_PG_ADMIN_DSN is not set`, `OT_PG_DSN_PAGES is missing in .env`).

`$OT_HOME/watch.toml` (read by `cmd/ot/watch.go`, the one parser of the file in `cmd/ot`; the format is defined here and owned by `docs/design/event-sources.md` Decision 1; the valuation loader follows this contract): one `[[underlying]]` table per company with `issuer` (`cik:<10 digits>` or `edinet:<code>`), `market` (`US` or `JP`), `symbol`, `sec_type`, `exchange`, `currency`, `con_id` (the IBKR contract) and three optional text keys: `report_date_override` (`YYYY-MM-DD`) and the two prices below. A missing file is an empty list. The file is loaded into `[]jobs.WatchEntry` at the start of `run-once`, `backfill` and `scheduler`. A refusal stops the command before any store is opened and names the issuer and the rule, never a path and never another value: an unknown market, a duplicate issuer, a malformed issuer, a malformed `report_date_override`, a `buy_price` or `sale_price` that is not a positive decimal with at most 4 places (a bare TOML number or date is refused too: quote it), or a `sale_price` below the `buy_price` of the same entry. Invalid TOML or an unknown key is refused by the fixed text `watch.toml is not valid`.

The prices of an entry:

- `buy_price`: decimal text in the currency of the contract, positive, at most 4 places; an empty text is unset.
- `sale_price`: the same, and not below the `buy_price` of the same entry.

`.env` rules (`setup.ReadEnv`, called through `deps.readEnv`):

- The file is `$OT_HOME/.env`; with `OT_HOME` unset the error is `OT_HOME is not set`.
- Lines are `KEY=VALUE`; a line without `=` is skipped. Blank lines and lines starting with `#` are skipped. Key and value are trimmed of white space.
- One pair of surrounding quotes (both `"` or both `'`) is removed from the value; nothing else is unquoted.
- The process environment is untouched: the file is read into a map and no variable is set.
- An error names the path and never a value (`env file PATH cannot be read`).

Profile rules (`internal/profile.Load`, which reads `OT_HOME` and `OT_PROFILE`, and `OT_ZONE` for the real profile only):

- The profile is demo when `OT_HOME` is unset, and also when `OT_PROFILE=demo`. With `OT_HOME` set and `OT_PROFILE` unset or `real`, it is real.
- `Load` reads `OT_ZONE` for the real profile: it names the owner's zone, and unset or invalid is a bad profile. The demo profile has the zone `UTC` and does not read `OT_ZONE`.
- `OT_PROFILE=real` needs `OT_HOME`; without it the profile is bad.
- An `OT_PROFILE` that is neither demo nor real is a bad profile.
- In the demo profile `page` uses the built-in demo points of DGS10 and `serve` those of the seven macro series, and neither opens a store; `run-once`, `backfill`, `migrate` and `calendar load` refuse it (an error that says the demo profile opens no store). `version` and `setup pg` do not look at the profile name; `setup pg` still needs `OT_HOME`.

Calendar file format (`ot calendar load`): one JSON object per file with two keys.

- `provenance`: an object with five keys, all non-empty strings: `generator`, `generator_version`, `source_library`, `source_library_version` and `generated_at`. `generated_at` is a time in RFC 3339. The loader invents none of them; a missing `provenance` is an error.
- `rows`: a non-empty list of session days, each with `calendar_id`, `session_day`, `is_session`, `open_at`, `close_at` and `early_close`.

Row rules, checked for every file before anything is written:

- `calendar_id` is set.
- `session_day` is strictly ascending within one `calendar_id`.
- On a session day (`is_session` true), `open_at` is before `close_at`.
- On a closed day (`is_session` false), `open_at` equals `close_at` and `early_close` is false.

## Outputs

- `ot version` writes `ot dev (profile demo)` to standard output: the format is `ot <version> (profile <profile>)` and a newline; the version is `dev` unless set at build time with `-ldflags "-X main.version=..."`; the profile is `demo` or `real`.
- `ot page` writes the page bytes the builder returned to standard output, or to the file of `--out` (mode 0644).
- `ot serve` listens on `--addr` and logs `serve listening`. A live page is built anew for each request, with the day of `--day` or else today in the market zone at that request. When the build fails it answers 500 with the fixed text `internal error`; no error text reaches the client. A failed listen is an error that names the address. On interrupt it shuts down with a 5 second grace.
- `ot run-once`, `ot backfill`, `ot setup pg`, `ot migrate` and `ot calendar load` write nothing to standard output; they log one line with `status=ok` on success (`ot run-once` only when `Reconcile` ran and returned nil). `ot backfill` logs `backfill <day> done` with `status=ok` and the counts `already_present`, `filled`, `absent` and `missing`; it exits 1 when the day was refused or any selected key is `Missing` (the message names the count); `Absent` is not an error, exit 0.
- Error texts of `ot setup pg` withhold the underlying error, because it may hold `OT_PG_ADMIN_DSN`: the text says the error text is withheld. `ot migrate` never logs the text of a wrapped error either; it turns the error into a text by four rules, in this order: (1) an error with no wrapped error whose text starts with `setup: migrate: ` is a fixed-text stage error of setup (parse, connect, role, schema) and is logged as is; (2) otherwise, a `goose.PartialError` in the chain gives the migration version, and an error of the chain with a `SQLState()` method (a `pgconn.PgError` has one; `cmd/ot` does not import pgx) gives its SQLSTATE and its own message; (3) SQLSTATE `42704` with a message that names a role adds the hint `run ot setup pg first`; (4) any other error keeps the withheld text. The DSN and its parts never appear.
- Before it reads or connects to anything with the administrative DSN, `ot migrate` checks that `--dir` is an existing directory holding at least one `*.sql` file (after the demo-profile and unset-DSN checks, before the migration run); otherwise it fails with the fixed text `migrate: --dir "<path as given>" is not a directory with .sql files; pass --dir <repository>/migrations`. The path is not a secret; the DSN never appears.
- The error texts of the open and load steps of the calendar loader keep that fixed text and say it is withheld because it may hold `OT_PG_DSN_LOADER`.
- An error at the command boundary never wraps a pgx error. This holds for every command that takes a DSN (`backfill`, `calendar`, `migrate`, `setup`, `page`, `run-once`, `serve`): the error is a new text of fixed wording that names a stage and a line, never the text of the connection error. The calendar file errors name the path, and the row errors the row index and the rule, never a value.

Exit codes, each tied to its condition:

- Exit code 2: the profile is bad (an error line starting `ot:` on standard error), or the command is unknown or missing (the usage text on standard error).
- Exit code 75: `ot scheduler` stops because another build replaced it (it drained first); a supervisor restarts it. Any other stop of `ot scheduler` but a drain (the lock held, the fence lost, the loop frozen) exits non-zero, never 75. A command reports its code by returning an `exitError`; `run` returns that code and keeps 1 for any other error.
- Exit code 1: a command fails; the log line is `command failed` with the error text, and this includes a flag parse error.
- Exit code 0: success.

## Invariants

- The profile is chosen once, before the command, and a bad profile stops the start before any command runs: even `version` exits 2.
- Standard error carries logs and usage; standard output carries the output of the command only.
- No value of a DSN, key or password appears in an error, a log line or this document.
- `ot calendar load` reads and checks every file before it opens a store; a bad file writes nothing. It loads the files one after the other in the order given. The load is idempotent: loading a file twice gives the same rows.
- `ot calendar load` opens the store with the DSN of `ot_loader` from `OT_PG_DSN_LOADER` and closes it on every path. It reads no administrative DSN and has no fallback: a missing or empty line is an error that names the line and says `ot setup pg` creates it. Every check of the files comes before `.env` is read.
- `ot run-once` and `ot backfill` close every store they opened on every path.
- `ot page` and `ot serve` open no store in the demo profile.
- `ot page --name market_page [--day DAY]` builds the page in the zone of the profile through `deps.marketPage` (run id `ot-page`, scope `market`; `cmd/ot/market.go`) from the winner readings of the reading view opened once per command with `OT_PG_DSN_PAGES` (role `ot_ro_pages`) and from the series store of `seriesReader`; a missing line is an error naming the line, a nil zone is an error before any store is opened; the demo profile opens no store and reads fixed demo readings carrying `data_day`.
- `ot serve` serves the route `/health` (`cmd/ot/site.go`), before any page route: GET and HEAD only, another method 405 with `Allow: GET, HEAD`. It reads one range of series `DGS10` on today's market day from the series reader under a 2 second timeout of the request context. No error: 200, `Content-Type: application/json`, body `{"status":"ok"}`. Any error: 503, body `{"status":"unavailable"}`, and the log line `serve health failed` with `component=ot status=failed` and no error text. The demo profile answers 200. A container passes `--addr :8080` (all interfaces); the default of `--addr` stays the loopback `127.0.0.1:8080`.
- `ot serve` serves the route `/market` (`cmd/ot/market_site.go`): GET and HEAD only, `/market/x` is 404, another method 405, a reader error 500 with the fixed text `internal error`. It builds `market_page` per request for the requested day through `deps.marketPage` (run id `ot-serve`, scope `market`) from the winner readings of the reading view and the series store opened once per process with `OT_PG_DSN_PAGES` (role `ot_ro_pages`); the route opens nothing itself. The demo profile opens no store and reads fixed demo readings carrying `data_day`. `/market` is not an item of the bar of eight: it is reached by its address, a named exception to `docs/design/unified-site.md`.
- `ot serve` serves the route `/options/candidates` (`cmd/ot/candidates_site.go`): GET and HEAD only, `/options/candidates/x` is 404, another method 405, a build error 500 with the fixed text `internal error`. It builds `option_candidates_page` per request for the day of `--day` or else today through `deps.optionCandidatesPage` (run id `ot-serve`, scope `candidates`) from the candidate store opened once per process with `OT_PG_DSN_PAGES` (role `ot_ro_pages`, through `candidate.Open`; closed on exit, so `ot serve` opens eight stores); the lookback over earlier days is the builder's. The demo profile reads fixed demo rows (two ok and one blocked row of each of the three kinds) and opens no store. The ninth item of the bar that links to it belongs to the web build, not to `cmd/ot`.
- `ot page --name option_candidates_page [--day DAY]` builds the same page through `deps.optionCandidatesPage` (run id `ot-page`, scope `candidates`) in the zone of the profile (a nil zone is an error before any store is opened) from the candidate store opened once with `OT_PG_DSN_PAGES`; a missing line gives no reader, so the page shows its gap `no_reader`; the demo profile reads the demo rows.
- `--name` of `ot page` accepts `macro_rates` (default), `macro_page`, `report_page`, `market_page` and `option_candidates_page`; `macro_page` is built in the zone of the profile (`pageNamed`, `cmd/ot/pagelist.go`), an unknown name is an error that lists the names of the page list, `macro_page`, `report_page` and `market_page`, and the run id `ot-page` reaches no ledger row. `ot serve` has no `--name`.
- `cmd/ot` calls constructors through the `deps` struct, which a test fills with fakes; no test connects to a live broker or database.

## Forbidden

- Writing a value of a DSN, API key or password to a log line, an error, standard output or a file.
- Setting a process environment variable from `.env`.
- Opening a store in the demo profile for `page` or `serve`, or running `run-once`, `migrate` or `calendar load` in it.
- Returning the text of a build error to an HTTP client.
- Inventing provenance for a calendar file, or writing a row of a file that failed a check.
- A test that connects to a live broker or database, or sleeps.
