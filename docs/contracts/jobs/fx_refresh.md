# fx_refresh

## fx_refresh

- `fxrefresh.NewFxRefreshFunc` (implemented by `internal/jobs/fxrefresh.New`; design `docs/design/market-bars.md`, Decision 9): `func(broker.Broker, broker.HistoryClient, bar.FxRateWriter, bar.FxRateReader, clock.Clock) (contracts.Job, error)`.
- Id `fx_refresh`; one key `{obs.fx_rate, USDJPY}`; schedule `XNYS`, `session_close`, offset 15 minutes, `run_bound` 10 minutes; `job.toml` also holds `duration_days` (5), `sources = ["ibkr_midpoint", "fred_h10"]` and `fill_lookback_days` (14).
- `Run` first asserts the writer to `bar.FxRateUpserter` (design `docs/design/data-repair-fx.md`, Decisions 4, 6, 8); a writer without `UpsertFxRates` (no bar DSN) makes `Run` return a Retryable error naming the missing bar store, before any broker call, and never falls back to `InsertFxRates`. It resolves the USD.JPY cash contract once through `Broker.ResolveContract` (sec type `CASH`, symbol `USD`, exchange `IDEALPRO`, currency `JPY`; not listed is Permanent) and asks `MIDPOINT` for 5 days with `End` set to the day when the day is before the UTC date of the clock and empty otherwise. Bars whose day is after the day are dropped; the rest are upserted by key in one `UpsertFxRates` call with `writtenBy` `fx_refresh:<day>` (`rate` is the close text, `source` `ibkr_midpoint`). A differing stored rate is replaced, an equal one (numerically) is untouched, and no old value is kept. The job no longer reads the stored days. An empty answer replaces nothing, writes nothing, returns zero rows and fabricates nothing; no default rate exists in the package. A history or store error is Retryable unless it is already typed; a close that is not a positive decimal and a bar day that does not parse are Permanent.
- Rank (design `docs/design/source-rank.md`, Decisions 1 to 3, 7, 10): the order of `sources` in `job.toml` is the rank. The first name is the primary (the upsert above); every later name is a fill source, written by `InsertFxRates` only. `New` returns an error when the list is empty, does not start with `ibkr_midpoint`, or names a source other than `ibkr_midpoint` and `fred_h10`, or when `fill_lookback_days` is not positive.
- Fill: `fxrefresh.AttachSecondary` (an `AttachSecondaryFunc`) attaches a `sources.Source` to a job `New` built and returns false for any other `contracts.Job`; a job without a source makes no fill call. After the primary step, whatever its result (an IBKR failure or an empty answer included), `Run` asks the source for `DEXJPUS` over `[day - 14 days, day]` directly, not through any stored series, and inserts each point whose value is present and positive as source `fred_h10` with the shortest decimal text of the value (153.42 is `"153.42"`). A nil, zero or negative point is not written. A stored row of any source is never replaced by the fill. A failed fetch or insert is logged and never changes the `Run` result, which is always the primary's. A run of any day does the fill; there is no time-of-day guard.
- A filled day is FRED's H.10 rate (the noon New York buying rate, 2 decimals), not an IBKR midpoint, marked by `source = fred_h10`. It stays until a forced `fx_refresh` of a day inside the five-day window: the primary's upsert replaces it because the source differs. A day older than the window keeps FRED's rate.
