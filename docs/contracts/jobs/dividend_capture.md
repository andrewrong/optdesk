# dividend_capture

## dividend_capture

`dividendcapture.NewDividendCaptureFunc(broker.ReferenceClient, store.InstrumentResolver, dividend.Writer, dividend.Reader, []jobs.WatchEntry, clock.Clock)` builds the job `dividend_capture` (implementation: `internal/jobs/dividendcapture.New`); the design is `docs/design/event-sources.md#Decisions` (2, 5, 6, 7).

- Id `dividend_capture`; schedule `XNYS`, `session_close`, offset 30 minutes, `run_bound` 10 minutes; key `{obs.dividend_expectation, <issuer>}` per entry. `New` refuses a nil argument, an entry with an empty or duplicate issuer and a market other than `US` or `JP`.
- `job.toml` holds `passed_markets`, the markets whose probe passed in `docs/design/event-sources-probe.txt`; the owner copies them there. It is the run-time input: an entry of a market not in it gets an `unsupported` row with source `none` and is not asked.
- `Run` resolves each entry to its `instrument_id` with the identifier scheme `ibkr_conid`, makes one `ReferenceClient.Dividends` call for the entries of the passed markets, and upserts one row per stock, one row per call, through `fundkey.DividendUpserter` (design `docs/design/fundamentals-keys.md#7 fundamentals-keys-dividend-job`), attempt 1: `present` (parsable next ex-date and amount; decimal text from the tick), `no_value`, or `error` with `error_code` `timeout` (tick timeout), `ibkr_<code>` or `error_status` (error status), `request_failed` (the call failed) or `bad_answer` (wrong number of answers). Source is `ibkr_tick_456`, except `unsupported` and `resolve_failed` rows, which have `none`.
- A failed resolve is an `error` row `resolve_failed` for that stock only; the row is keyed by the `con_id` of the entry, since the writer refuses instrument id 0, and the stock is not asked. One stock failing does not stop the others. The job keeps no skip of a stored day: a rerun replaces what the broker now says. A row the store refuses is logged and not counted as returned, the loop goes on, and the first refusal is the Retryable error of the run, after the other rows are tried.
- Upsert: `Run` asserts the writer to `fundkey.DividendUpserter` and returns a Retryable error naming the missing `UpsertDividends` when it is absent (`New` does not fail). `writtenBy` is `dividend_capture:<day>`. A day before the clock's date in the manifest zone (`America/New_York`) is a replay and calls `ReplayDividends`, any other day `UpsertDividends`. Test: `TestRunWithoutUpserterIsRetryable`, `TestPastDayIsAnswerDayAndUsesReplay`, `TestRefusedRowDoesNotStopOthers`, `TestPresentAndResolveFailedRowsReachUpserter`.
- Day: the day given names the answer rows (`session_day`); there is no development-mode override. The vendor's answer is still the current one.
- Memo: the job memoises per instance and day the result of the first `Run`, which asked the broker and wrote; a later key of the same instance and day returns that result, a failure included, without a broker call, so one Plan makes one `Dividends` call. A new instance (a forced console run plans again) asks once more. Test: `TestSecondKeyOfOneInstanceDoesNotCallBroker`, `TestFailedFirstKeyIsMemoisedNoBrokerCall`.
- Contract tests: `internal/jobs/dividendcapture/run_test.go` `TestEmbeddedManifest` (the constructor type), `TestPresentRow`, `TestNoValueRow`, `TestTimeoutIsErrorRow`, `TestUnpassedMarketIsUnsupported`, `TestOneStockFailsOthersWritten`, `TestRowKeyedByResolvedInstrument`, `TestWholeCallFailureIsErrorRows`.
