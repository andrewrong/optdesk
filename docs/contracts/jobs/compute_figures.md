# compute_figures

## compute_figures

`computefigures.New(computefigures.ComputeStores, compute.Figures, compute.Rules, compute.Units, compute.SeriesOps, clock.Clock)` builds the job `compute_figures` (type `computefigures.NewComputeFiguresFunc`); the design is `docs/design/compute-figures.md`. `computefigures.ComputeStores` holds the seven store interfaces the job uses: `Catalog` (`store.OptionEodCatalog`), `OptionEod` (`store.OptionEodReader`), `Terms` (`store.OptionTermsReader`), `Names` (`store.InstrumentNameReader`), `SessionDays` (`store.SessionDayReader`), `Series` (`store.SeriesReader`) and `Readings` (`store.ReadingStore`). The job is declared here; its implementation is a later issue.

- HV30: `computefigures.ComputeStores.PriceBars` (`bar.PriceBarReader`, the last field, optional). With nil the job has no `market.hv30_own` key and runs no HV30 step. With it set, `Plan` adds one key `{readings.reading, "market.hv30_own|underlying|<name>"}` per underlying of the day (manifest key `hv30`), and `Run` stores it after IV30 and before the market figures: it reads the winner `trades` rows (never `adjusted_last`, never IBKR's HV30) from the as-of day minus 70 calendar days to the as-of day, and stores the figure of `Figures.HistoricalVol` as a reading, ok or missing with the figure's reason (`no_input`, `short_history`, `stale_input`), with the parameters `data_day`, `observations` and `window`. Design: `docs/design/market-bars.md` Decision 10.
- rv20: `Plan` always adds one key `{readings.reading, "market.rv20|underlying|<name>"}` per name of the manifest `rv20_indices` (`SPX`, `NDX`, `RUT`), whether or not the readers are set. `Run` routes the key by the rule name before the underlying case (never to IVP/IVR), resolves the name to an instrument id through `ComputeStores.IndexIDs` and stores the 20-day realised volatility from the winner `trades` closes with the HV30 step (rule `market.rv20`; `ok`, or `missing_input` with `no_input`, `short_history`, `stale_input` or `bad_input`). An absent reader fails the key as `Permanent` (`no price bar reader` when `PriceBars` is nil, `no index reader` when `IndexIDs` is nil) and nothing is stored for it, so a run never ends green with nothing stored; the other keys are still stored. A name with no index instrument fails `Retryable` (`no index instrument named X`: `bars_refresh` may create it later in the day); a name with two instrument rows fails `Permanent` (`ambiguous`). A read error of `IndexIDs` is `Retryable`. Design: `docs/design/market-rv20.md` Decisions 4 and 5.
- Ease: `computefigures.NewWithEase` (type `computefigures.NewComputeFiguresEaseFunc`) takes a `compute.Ease` after the `compute.SeriesOps` and before the clock; `New` is `NewWithEase` with nil. Only a job built with an `Ease` plans the key `{readings.reading, "macro.ease|market|WALCL"}`, and its `Postcondition` is a reading row of the as-of day, ok or missing, like every other key; a job built with nil has no `macro.ease` key and runs no ease step. The job reads the seven series of `[ease]` in `job.toml` and stores the reading of `docs/design/ease-v2.md` Decision 7. The ease is stored after the market figures and after IVP and IVR, so its failure (a series read that fails leaves the key without a row, named by the postcondition) stops no other key.
- Valuation: `computefigures.NewWithValuation` (type `computefigures.NewComputeFiguresValuationFunc`, declared in `internal/jobs/computefigures/types.go` with `computefigures.ValuationDeps`; design `docs/design/valuation.md#valuation-job-step`) takes the `ValuationDeps` after the `compute.SeriesOps` and before the clock. `ValuationDeps` holds `Facts` (`store.FactReader`), `Entries` (`[]jobs.WatchEntry`) and the functions `StandardOf`, `BuildFilings`, `Band`, `Questions`, `Diagnosis` (the `valuationapi` types of the same names). With any function nil the job is the plain one and its plan has no `valuation.` key. With all set, `Plan` adds, per entry with an issuer, the keys `{readings.reading, "valuation.buy_band|underlying|<Contract.Symbol>"}`, `valuation.question` and `valuation.diagnosis`; `Run` reads `Facts.FactsFiledBy(source, issuer, day)` (source `edinet` for an `edinet:` issuer, else `sec`), takes the standard from `StandardOf`, calls `BuildFilings` and writes one reading per key through `ComputeStores.Readings`. The band reading is `ok` with the 8% value as `value` and `low`, `ref_high`, `base_fy_end`, `flag` as parameters; an empty standard gives `missing_input` with the parameter `reason` `no_standard`; a refusal of `BuildFilings` gives `missing_input` with its reasons as `reason` parameters, and a financial or cyclical company (state `unvalued`) still gets its diagnosis reading. `question` and `diagnosis` readings have as `value` the count of figures that are ok and one parameter per figure (`<key>` its value, `<key>.reason` its reason; `group` for the diagnosis); none ok is `missing_input`. A second run of a day writes no new rev for an unchanged state, reasons, parameters and rows hash. `Postcondition` and the schedule are the plain job's. Test: `internal/jobs/computefigures/valuation_test.go` `TestNilFuncsNoValuationKey`, `TestStandardFromFacts`, `TestThreeReadingsPerCompany`, `TestBankGivesMissingInputBand`; `valuation_api_test.go` `TestValuationDepsContract`.
- Keys: one `{readings.reading, "name|subject_kind|subject"}` per (rule, subject). `subject_kind` is `underlying` (subject is the symbol of `InstrumentNames`, else `underlying:<id>`) or `market` (subject is the FRED id of the first input).
- Steps, in order: IV30, then the market figures, then IVP and IVR from the stored IV30 readings, so a missing IV30 gives a missing IVP with `no_input`.
- IBKR IVP (design `docs/design/compute-stage2.md#9-ivp-ibkr-step`, Decisions 3 and 12): `Plan` adds `{readings.reading, "market.ivp_ibkr|underlying|<name>"}` per underlying (manifest keys `iv_ibkr`, `ivp_ibkr`); `runIvStats` stores it from the stored `market.iv_ibkr` readings with the same `IvPercentile` (252 valid sessions, else `short_history`; no ok reading of the as-of day gives `no_input`); no IVR is planned for it. `market.ivp_own` never reads the IBKR series and the two are never mixed in one window. Precedence (Decision 3), applied by the page that reads them, not by the job: `market.ivp_own` when ok, else `market.ivp_ibkr` when ok, else the gap with the reason of `market.ivp_own`. A step that fails does not stop the others; its keys are written missing or stay absent, and the postcondition names them.
- As-of day: the slot day. `Postcondition`: every planned key has a reading row for the as-of day, ok or missing.
- Iv30 input rules (Decision 10): subjects are the underlyings of `OptionEodCatalog.OptionEodLatest(ctx, day)` that have a row of the day itself in `OptionEod(ctx, id, day, day)`, named by `InstrumentNames`. Of one `instrument_id` the row with the latest `received_at` is used, and only `status` 1. `OptionTerms` is asked in chunks of 500 ids; a row without a current terms version is dropped and counted. The mid is (bid+ask)/2 when both are present, `ask >= bid` and `ask > 0`, else that side is absent; an IV absent or not above 0 is 0. `T` runs from the close of the as-of day's session row (calendar `XNYS`) to the `close_at` of the expiration day's session row, or its `open_at` for an `AM` settlement; an expiration day that is not a session day drops that expiry; minutes are floored. The rate is the newest `DGS3MO` point not after the as-of day; none gives a missing `no_input`; a point more than 4 calendar days before the as-of day (`max_age_days` of `market.iv30_own`) gives a missing `stale_input` (stored `missing_input`, `reason_code` 3); a point of an earlier day within 4 calendar days is used and the parameter `stale_rate` is true.
- Retry classes: a store error is `Retryable`; a bad rule (an unknown id or version, a rule the core rejects) is `Permanent`. A figure the core marks missing is stored `missing_input` with its reason, never skipped.

## Version history

- v1: `compute_figures`, interface only (`computefigures.ComputeStores`, `computefigures.NewComputeFiguresFunc`).
- rv20: `compute_figures` plans and stores `market.rv20` for SPX, NDX and RUT (additive keys; an absent reader fails the key `Permanent`). Seams, declared earlier: `computefigures.ComputeStores.IndexIDs` is an optional field of type `computefigures.IndexIDReader` (`IndexIDs(ctx, names []string) ([]store.InstrumentName, error)`: the instruments of type `index` whose name is in names, ordered by id); `IndexIDStore` adds `Close() error` and `OpenIndexIDsFunc` opens one from a dsn. The manifest keys `rv20 = "market.rv20"` and `rv20_indices = ["SPX", "NDX", "RUT"]` are parsed. The plan and the run use them (see the rv20 line above). Design: `docs/design/market-rv20.md` Decision 4.
- v1: `compute_figures` stores `market.hv30_own` when `ComputeStores.PriceBars` is set (additive field).
- v1: `compute_figures` stores `market.ivp_ibkr` per underlying from the stored `market.iv_ibkr` readings (additive; manifest keys `iv_ibkr`, `ivp_ibkr`).
- v1: `compute_figures` stores `macro.ease` when built with an `Ease` (`computefigures.NewComputeFiguresEaseFunc`, additive).
- v1: `compute_figures` stores `valuation.buy_band`, `valuation.question` and `valuation.diagnosis` per watched company when built with `computefigures.NewWithValuation` and all `ValuationDeps` functions (`computefigures.NewComputeFiguresValuationFunc`, additive).
