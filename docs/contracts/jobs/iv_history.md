# iv_history

## iv_history

- `ivhistory.New(h broker.HistoryClient, r store.ReadingReader, w store.ReadingWriter, entries []jobs.WatchEntry, ivText func(close string) (string, error), clk clock.Clock) (contracts.Job, error)` builds the job `iv_history` from its embedded `job.toml`; design `docs/design/compute-stage2.md#7-iv-history-job` (Decisions 9 and 11). `cmd/ot` passes `ivbar.FromClose` as `ivText`, so the package imports no compute package. `internal/jobs/api.go` declares no type for it. The constructor refuses a nil argument, an entry without a symbol (or with a `|` in it) and a repeated symbol.
- `ivhistory.LoadManifest(data)` and `ivhistory.DefaultManifest()` read `job.toml`. Keys: `version`, `id` (`iv_history`), `reading` (`market.iv_ibkr`), `reading_version` (1), `convention` (`ibkr_iv_bar_v1`), `backfill_days` (400), `daily_days` (5), `lookback_days` (365), and `[schedule]`: calendar `XNYS`, anchor `session_close`, offset `10m` (before `compute_figures`, 20 minutes; apart from `bars_refresh`), `run_bound` `10m`. The slot is a proposal; the owner confirms it as for the other jobs. A missing `id`, `reading`, `convention` or `schedule.calendar` and a non-positive number are refused with the key named and never the value.
- `Plan(day)`: one key `{readings.reading, market.iv_ibkr|underlying|<symbol>}` per entry, named by the symbol of its contract, sorted, and the hash of the job id, version, day and keys.
- `Run`: for each key one `Bars` request of kind `broker.BarOptionImpliedVol`, 400 days when the name has no ok `market.iv_ibkr` reading in the last 365 days, else 5 days. Each bar on or before the day becomes one reading (`subject_kind` `underlying`, `origin` `ibkr`, unit `decimal`, one input row `ibkr.bars` keyed `<name>|<day>`), ok with the text `ivText` gives for the close, else missing `bad_input` (reason 5). When no bar of the day arrived (an empty answer too, and a broker answer of "no data", error 162, which `isNoData` tests by the text `broker error 162`) a missing `no_input` (reason 1) reading of the day is stored. A day already stored ok is left as it is; a stored missing day is replaced by an ok reading at the next rev; a rerun writes nothing new. `Run` asserts the writer to `readingkey.ReadingUpserter` and writes the rows of all its keys in one `UpsertReadings` call (a day is in the call once, the last bar of a repeated day winning); a writer without the method is a `Retryable` error naming `UpsertReadings`, and a failed write is `Retryable` for the keys that had rows in it. `Returned` is the keys that hold a reading of the day, `Usable` those whose reading is ok. A history or store error is `Retryable` unless already typed (a paced answer is retried by the job runner, as for `bars_refresh`); an unknown key is `Permanent`.
- Contract tests: `internal/jobs/ivhistory/job_test.go` and `run_test.go` (`TestBootstrapAsks400Days`, `TestLaterRunAsks5Days`, `TestStoresOneReadingPerBar`, `TestMissingBarOfDayIsNoInput`, `TestBadCloseIsBadInput`, `TestRerunInsertsNothingNew`, `TestPostconditionFollowsDayReading`, `TestPacedAnswerIsRetryable`, `TestNoDataAnswerIsNoInput`, `TestNoDataRerunStoresNothingNew`, `TestOtherBrokerErrorStaysFailed`, `TestRunWithoutUpsertIsRetryable`, `TestStoredMissingOfDayIsReplacedInUpsert`, `TestStoredOkIsNotSentAgain`, `TestRunWritesAllKeysInOneCall`, `TestRunRepeatedBarDayKeepsLastBar`).
